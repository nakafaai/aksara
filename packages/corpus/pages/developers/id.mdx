# Sumber Daya Pengembang Nakafa

Terakhir diperbarui: 25 Agustus 2026

Nakafa menyediakan akses publik yang dapat dibaca mesin ke materi belajar multibahasa dan referensi Quran dengan rentang terbatas. Antarmuka ini cocok untuk agen dan aplikasi yang memerlukan input bertipe, kegagalan yang dapat diprediksi, dan referensi konten kanonis. Semua akses bersifat baca-saja, tidak memerlukan akun Nakafa, serta tidak membuka data pelajar privat, pembelian, atau tindakan akun.

## REST API publik

Alamat dasar API kanonis adalah [https://api.nakafa.com/v1](https://api.nakafa.com/v1). Mulai dari indeks layanan dan gunakan pencarian untuk menemukan hasil yang relevan. Ambil hasil melalui ID konten hanya jika hasil tersebut memuat `markdown_url`. Hasil katalog try-out tanpa `markdown_url` hanya untuk sitasi dan menautkan URL aplikasi kanonisnya. API juga menyediakan taksonomi terbitan dan referensi ayat Quran dengan rentang yang jelas.

- `GET /v1`: identitas layanan dan tautan penemuan
- `GET /v1/health`: kesehatan layanan
- `GET /v1/search`: pencarian berdasarkan kueri, bagian, bahasa, limit, dan offset
- `GET /v1/content?ref=...`: pengambilan ID konten atau URL kanonis yang tepat
- `GET /v1/taxonomy`: taksonomi terbitan
- `GET /v1/quran/{surah}`: pengambilan rentang ayat bertipe

Pencarian mengembalikan 10 hasil secara bawaan dan menerima maksimum 50 hasil per permintaan. Gunakan `offset`, `has_more`, dan `next_offset` untuk melanjutkan kumpulan hasil tanpa menebak. Klien sebaiknya membatasi anggaran hingga 120 permintaan per 60 detik dari satu IP dan menangani respons HTTP 429 dengan jeda bertahap.

## OpenAPI dan kegagalan

[Kontrak OpenAPI 3.1 Nakafa](https://api.nakafa.com/openapi.json) menjelaskan setiap operasi publik, input, respons, dan contoh. Penambahan yang kompatibel tetap berada di `v1`. Perubahan yang merusak kontrak memerlukan jalur mayor baru.

Kegagalan API yang berasal dari Convex menggunakan RFC 9457 Problem Details dengan media type `application/problem+json`. Setiap respons memuat `code` yang stabil, `detail` yang mudah dipahami, `resolution` yang dapat dikerjakan, dan `request_id` yang dapat ditelusuri. HTTP 429 dari Vercel Firewall dapat menghentikan permintaan sebelum mencapai Convex, sehingga klien harus memperlakukannya sebagai pengecualian milik platform dan mencoba lagi dengan jeda bertahap.

## Model Context Protocol

Endpoint MCP kanonis berada di [https://mcp.nakafa.com/mcp](https://mcp.nakafa.com/mcp). Gunakan MCP ketika agen sudah mendukung penemuan tool dan pemanggilan tool terstruktur. Gunakan REST untuk integrasi HTTP biasa atau klien yang dibuat dari OpenAPI. Kedua antarmuka menjalankan kapabilitas yang sama di Convex dan memverifikasi publikasi Aksara bertanda tangan yang sama.

Server menyediakan empat tool baca-saja:

- `nakafa_search_content`
- `nakafa_get_content`
- `nakafa_get_taxonomy`
- `nakafa_get_quran_reference`

Klien modern menggunakan Streamable HTTP. Protokol `2026-07-28` menggantikan siklus `initialize` lama dengan `server/discover` dan envelope `_meta` pada setiap permintaan. Klien terlebih dahulu menemukan revisi yang didukung, lalu membuat daftar atau memanggil tool dengan envelope yang sama. Nakafa menerima revisi protokol yang didokumentasikan ini dan melaporkan semua revisi yang didukung melalui penemuan. Identitas dan kapabilitas server berasal dari respons `server/discover`. Endpoint stateless Nakafa tidak menyediakan manifest `GET` terpisah.

## Baris perintah

Paket resmi untuk Node 24 bernama `nakafa-cli`, dengan executable `nakafa`. CLI memanggil REST API publik dan mencetak JSON ringkas secara bawaan. Tambahkan `--pretty` untuk keluaran yang mudah dibaca atau `--api-base` saat memverifikasi endpoint API kompatibel yang berjalan secara lokal atau dihosting secara mandiri.

<CodeBlock
  data={[{
    language: "bash",
    filename: "nakafa-cli.sh",
    code: `npm install --global nakafa-cli
nakafa search persamaan linear
nakafa quran 1 --from-verse 1 --to-verse 7 --pretty
nakafa mcp`
  }]}
/>

CLI mempertahankan JSON Problem Details pada standard error dan menggunakan kategori exit bukan nol yang stabil untuk kegagalan pemanggilan, API, serta jaringan atau server.
