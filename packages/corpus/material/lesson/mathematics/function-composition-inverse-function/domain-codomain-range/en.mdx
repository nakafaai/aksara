## Domain

The **domain** is the set of all inputs for which a function is defined. An input outside this set cannot be evaluated by that function.

### Finding the Domain Example

Consider the function:

<BlockMath math="f(x) = \frac{1}{x}" />

The rule divides <InlineMath math="1" /> by the input. Testing <InlineMath math="0" /> exposes the restriction:

<BlockMath math="f(0) = \frac{1}{0}" />

Division by zero is undefined, so <InlineMath math="0" /> is excluded while every other real number is allowed.

So, the domain of the function <InlineMath math="f(x) = \frac{1}{x}" /> is all real numbers except <InlineMath math="0" />.

Another example:

<BlockMath math="g(x) = \sqrt{x}" />

This rule takes the square root of its input. Testing <InlineMath math="-4" /> gives:

<BlockMath math="g(-4) = \sqrt{-4}" />

Over the real numbers, a square root requires a nonnegative radicand. Therefore, only <InlineMath math="0" /> and positive inputs are allowed.

So, the domain of the function <InlineMath math="g(x) = \sqrt{x}" /> is all real numbers greater than or equal to <InlineMath math="0" /> (<InlineMath math="x \ge 0" />).

## Codomain

The **codomain** is the target set declared as part of a function's definition. Every output must belong to this set, but the function does not have to reach every member of it.

For example, let's define a function <InlineMath math="f(x) = 2x" />.

We specify the **Domain** (input) as the set of natural numbers:

<BlockMath math="\{1, 2, 3, ...\}" />

Then, we specify the **codomain** as the set of integers:

<BlockMath math="\{..., -2, -1, 0, 1, 2, ...\}" />

By choosing the integers as the codomain, we declare the set in which every value of <InlineMath math="f(x)=2x" /> must lie. For natural-number inputs, the function actually produces only positive even numbers. Those attained values form the range:

<BlockMath math="\{2, 4, 6, ...\}" />

The chosen codomain is valid because every actual result in the range is an integer.

The codomain therefore describes the permitted target space. It is not a list of values the function necessarily produces.

## Range

The Range is the **collection of all output values that are _actually_ produced** by the function when we input all members of the domain. The Range is part of (or sometimes exactly the same as) the Codomain.

**Example:**

Let's use the function <InlineMath math="f(x) = x^2" /> again.

Suppose the Domain is the set of integers:

<BlockMath math="\{..., -2, -1, 0, 1, 2, ...\}" />

and the Codomain is also the set of integers.

When we input values from the domain:

- <InlineMath math="f(-2) = 4" />
- <InlineMath math="f(-1) = 1" />
- <InlineMath math="f(0) = 0" />
- <InlineMath math="f(1) = 1" />
- <InlineMath math="f(2) = 4" />
- and so on...

The values that _actually_ come out as output are <InlineMath math="0, 1, 4, 9, 16" />, and so on (non-negative square numbers).

So, the **Range** of this function (with this domain) is the set:

<BlockMath math="\{0, 1, 4, 9, 16, ...\}" />

Notice that this range (<InlineMath math="\{0, 1, 4, 9, ...\}" />) is a part (subset) of the codomain we defined (integers):

<BlockMath math="\{..., -1, 0, 1, 2, ...\}" />

Not all members of the codomain are part of the range.

## Why Is This Important?

Domain, codomain, and range answer different questions. The domain prevents invalid inputs such as division by zero. The codomain declares the target space, while the range identifies the values the function actually reaches.

## Mathematical Relationship

Mathematically, a function <InlineMath math="f" /> maps every element from the set Domain (<InlineMath math="D" />) to one element in the set Codomain (<InlineMath math="K" />). This is often written as:

<BlockMath math="f: D \to K" />

The Range (<InlineMath math="R" />) is the set of all actual results <InlineMath math="f(x)" /> for every <InlineMath math="x" /> in the Domain. In other words:

<BlockMath math="R = \{ f(x) \mid x \in D \}" />

The important relationship between the three is that the Range is always a subset of the Codomain:

<BlockMath math="R \subseteq K" />

Every value actually reached by the function must belong to the codomain. The reverse is not required: a codomain value may never occur as an output.

## Check Your Understanding

Let <InlineMath math="h:\mathbb{R}\setminus\{2\}\to\mathbb{R}" /> be defined by <InlineMath math="h(x)=\frac1{x-2}" />.

1. Why is <InlineMath math="2" /> excluded from the domain?
2. Can <InlineMath math="0" /> belong to the range?
3. State the range of <InlineMath math="h" />.

### Worked Solutions

1. At <InlineMath math="x=2" />, the denominator is zero:

   <BlockMath math="h(2)=\frac1{2-2}=\frac10" />

   The expression is undefined, so <InlineMath math="2" /> cannot be in the domain.
2. No. A fraction with numerator <InlineMath math="1" /> cannot equal <InlineMath math="0" />.
3. Every nonzero real value is reached. Given <InlineMath math="y\neq0" />, choosing <InlineMath math="x=2+\frac1y" /> gives <InlineMath math="h(x)=y" />. Thus:

   <BlockMath math="R_h=\mathbb{R}\setminus\{0\}" />
