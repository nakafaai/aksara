## Choices That Meet Several Inequalities at Once

A plan may need to stay within a budget and meet a minimum attendance target at the same time. Each condition <Highlight>removes part of the possible choices</Highlight>. A linear inequality system describes the choices that satisfy every condition together.

### Linear Inequality System

A linear inequality system is a collection of two or more linear inequalities that must be **satisfied simultaneously**. For example, an upper bound has the form:

<BlockMath math="a_1x_1+a_2x_2+\cdots+a_nx_n\leq b" />

A lower bound uses the opposite comparison:

<BlockMath math="a_1x_1+a_2x_2+\cdots+a_nx_n\geq b" />

Where <InlineMath math="a_1, a_2, ..., a_n" /> are coefficients, <InlineMath math="x_1, x_2, ..., x_n" /> are variables, <InlineMath math="b" /> is a constant, and the inequality sign can be <InlineMath math="\leq, \geq, <, >" />.

The main difference between linear equations and linear inequalities is the relation between their two sides:

- A linear equation states that two expressions are equal (<InlineMath math="=" />)
- A linear inequality compares two expressions (<InlineMath math="\leq, \geq, <, >" />)

### Linear Inequality Systems with Two Variables

A system contains two or more inequalities with two variables (usually <InlineMath math="x" /> and <InlineMath math="y" />):

<BlockMath math="\begin{cases} a_1x + b_1y \leq c_1 \\ a_2x + b_2y \leq c_2 \end{cases}" />

**Example**:

<BlockMath math="\begin{cases} 2x + 5y < 10 \\ 6x + 2y > 10 \end{cases}" />

The solution to this system is the set of ordered pairs <InlineMath math="(x,y)" /> that satisfy all inequalities simultaneously.

## Solving Linear Inequality Systems

To solve a linear inequality system with two variables, we use the graphical method. Each inequality becomes a half-plane, and the solution is <Highlight>the region where all half-planes overlap</Highlight>. The steps below build that region in order.

### Draw the Boundary Lines

For each inequality, draw its boundary line by changing the inequality sign to an equals sign.

**Example**:

For the system:

<BlockMath math="\begin{cases} 2x + 5y < 10 \\ 6x + 2y > 10 \end{cases}" />

Draw the lines:

<BlockMath math="\begin{cases} 2x + 5y = 10 \\ 6x + 2y = 10 \end{cases}" />

### Determine the Solution Regions

To determine the solution region for each inequality:

1. Take a test point (e.g., the origin <InlineMath math="(0,0)" /> if it's not on the line)
2. Substitute it into the inequality
3. If the result is true, the region containing the test point is the solution region
4. If the result is false, the region not containing the test point is the solution region

**Example**:

For <InlineMath math="2x + 5y < 10" />, check point <InlineMath math="(0, 0)" />:

<BlockMath math="2(0) + 5(0) = 0 < 10" />

_(true)_

The solution region is the area containing point <InlineMath math="(0, 0)" />, which is below the line <InlineMath math="2x + 5y = 10" />.

For <InlineMath math="6x + 2y > 10" />, check point <InlineMath math="(0, 0)" />:

<BlockMath math="6(0) + 2(0) = 0 > 10" />

_(false)_

The solution region is the area not containing point <InlineMath math="(0, 0)" />, which is above the line <InlineMath math="6x + 2y = 10" />.

### Determine the Intersection of Solution Regions

The **intersection** contains points satisfying both conditions together. The point <InlineMath math="(2,1)" /> lies below the first line and above the second. Check by substituting both coordinates:

<MathContainer>
  <BlockMath math="2(2)+5(1)=9<10" />
  <BlockMath math="6(2)+2(1)=14>10" />
</MathContainer>

The point <InlineMath math="(0,0)" /> satisfies only the first condition, so it is not a solution of the system. With strict inequalities, **boundary points are excluded**, including the intersection of the two boundary lines.

Shade both conditions at once. The point <InlineMath math="(2, 1)" /> passes both tests, <InlineMath math="9 < 10" /> and <InlineMath math="14 > 10" />, so it lies in the overlap: the wedge that starts where the boundary lines meet at <InlineMath math="\left(\tfrac{15}{13}, \tfrac{20}{13}\right)" />. The boundary lines are not part of the solution, because both inequalities are strict.

### Graphical Representation

When drawing inequality graphs:

- For <InlineMath math="\leq" /> or <InlineMath math="\geq" />: use a solid line (the solution region includes points on the line)
- For <InlineMath math="<" /> or <InlineMath math=">" />: use a **dashed** line (the solution region does not include points on the line)
- The solution region is shaded to show the solution

## Check Your Understanding

<BlockMath math="\begin{cases} x+y\leq6 \\ 2x-y\geq0 \end{cases}" />

Determine whether <InlineMath math="(2,3)" /> and <InlineMath math="(1,5)" /> belong to the **solution set**.

### Worked Solution

When multiplying or dividing an inequality by a **negative number**, reverse the comparison sign. To graph the second constraint, use:

<BlockMath math="2x-y\ge0\quad\Longleftrightarrow\quad-y\ge-2x\quad\Longleftrightarrow\quad y\le2x" />

Substitute <InlineMath math="(2,3)" /> into both inequalities:

<MathContainer>
  <BlockMath math="2+3=5\leq6" />
  <BlockMath math="2(2)-3=1\geq0" />
</MathContainer>

Both statements are true, so <InlineMath math="(2,3)" /> is a solution.

Now test <InlineMath math="(1,5)" />:

<MathContainer>
  <BlockMath math="1+5=6\leq6" />
  <BlockMath math="2(1)-5=-3\not\geq0" />
</MathContainer>

The second statement is false, so <InlineMath math="(1,5)" /> is not a solution. The boundary lines meet at <InlineMath math="(2,4)" />, but that point is only one part of the solution. The full solution is the entire overlapping region, including only the parts of each solid boundary that satisfy the other inequality.

Draw both boundaries through their meeting point <InlineMath math="(2, 4)" />. The solution region lies below <InlineMath math="x + y = 6" /> and below <InlineMath math="y = 2x" />. The point <InlineMath math="(2, 3)" /> sits inside it, while <InlineMath math="(1, 5)" /> lies above the line <InlineMath math="y = 2x" />, which is why <InlineMath math="2(1) - 5 = -3" /> fails the second inequality.

## Modeling Feasible Choices

A linear inequality system describes the set of combinations that are **allowed together**. A word problem has to be turned into such a system before it can be solved, and the solution is the whole region of allowed combinations.

### Modeling Feasible Choices with Inequalities

Linear inequality systems describe the **feasible choices** in optimization problems, such as:

- Production problems with resource constraints
- Budget planning with cost constraints
- Nutrition planning with calorie constraints

An optimization model also needs an objective, such as minimizing cost or maximizing output. The inequalities alone define which choices are allowed.

### Activity Planning

Kiki is organizing an independence day celebration in her neighborhood. From the community fund, there is <InlineMath math="\text{Rp}500{,}000.00" /> available. For organizing competitions, it costs <InlineMath math="\text{Rp}20{,}000.00" /> per child. Prizes for winners are budgeted at <InlineMath math="\text{Rp}40{,}000.00" /> for **each type of competition**. It's expected that more than <InlineMath math="13" /> children will participate.

Define:

- <InlineMath math="x" /> = number of participants
- <InlineMath math="y" /> = number of competitions

The mathematical model is:

<BlockMath math="\begin{cases} 20{,}000x + 40{,}000y \leq 500{,}000 \\ x > 13 \\ x,y \in \mathbb{Z}_{>0} \end{cases}" />

If we simplify:

<BlockMath math="\begin{cases} 20x + 40y \leq 500 \\ x > 13 \\ x,y \in \mathbb{Z}_{>0} \end{cases}" />

Without the integer restriction, the cost and attendance constraints define a continuous feasible region. Because participants and competitions are counted in whole numbers, valid plans are the positive integer points inside that region.

### Maximizing the Number of Competitions

If Kiki wants **as many competitions as possible**, the objective is to maximize <InlineMath math="y" />. The participant count is an integer greater than <InlineMath math="13" />, so its smallest value is <InlineMath math="x=14" />. Divide the budget constraint by <InlineMath math="20{,}000" /> to obtain:

<BlockMath math="\begin{aligned}x+2y&amp;\le25\\14+2y&amp;\le25\\2y&amp;\le11\\y&amp;\le\frac{11}{2}\end{aligned}" />

The competition count must be an integer, so there can be at most **five competitions**. Six would require at least <InlineMath math="14+2(6)=26" /> cost units, above the limit <InlineMath math="25" />. Both plans below achieve five competitions:

| Participants | Competitions | Total cost |
| --- | --- | --- |
| <InlineMath math="14" /> | <InlineMath math="5" /> | <InlineMath math="\text{Rp}480{,}000" /> |
| <InlineMath math="15" /> | <InlineMath math="5" /> | <InlineMath math="\text{Rp}500{,}000" /> |

## Differences Between Linear Equation Systems and Linear Inequality Systems

The two system types differ in what counts as an answer. The table sets the operation sign, the solution form, and the graph side by side.

| Aspect                       | Linear Equation Systems                                   | Linear Inequality Systems                                                                        |
| ---------------------------- | --------------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| **Operation Sign**           | Uses equals sign (<InlineMath math="=" />)                | Uses inequality signs (<InlineMath math="<, >, \leq, \geq" />)                                   |
| **Solution Form**            | Common points of the equations                            | The common feasible set of all inequalities                                                      |
| **Graphical Representation** | Common points of lines                                     | Intersection of shaded half-planes                                                               |
| **Solution Methods**         | Substitution, elimination, determinants                   | Graphing, feasibility checks, and linear programming when an objective is present                 |
| **Number of Solutions**      | Zero, one, or infinitely many                              | May be empty, a point or boundary segment, or a region with infinitely many real solutions        |
| **Drawing**                  | Always uses solid lines                                   | Solid lines for <InlineMath math="\leq, \geq" /> and dashed lines for <InlineMath math="<, >" /> |

### How to Read the Visualization

In this interactive visualization:

1. **Boundary lines** show the equations (e.g., <InlineMath math="x + y = 10" /> and <InlineMath math="15x + 9y = 120" />)
2. **Colored regions** show the solution to each inequality
3. **Intersection region** (the area satisfying all inequalities) is the solution to the inequality system

The two boundary lines meet at <InlineMath math="(5,5)" />. This point forms one corner of the feasible set. The overlapping shading shows the part of the solution set visible in the graph window. The solution set does not end at the display edges.

The same reading order applies to a word problem: graph each condition, keep the permitted side, and then take the common region.
