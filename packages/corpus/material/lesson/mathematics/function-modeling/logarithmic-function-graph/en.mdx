## How the Base Shapes a Logarithmic Graph

A logarithmic graph <Highlight>changes quickly near its vertical asymptote</Highlight> and then more slowly as its input grows. This shape appears whenever an output records the logarithm of a positive ratio, including sound-level and pH scales. The base determines whether the graph increases or decreases, while transformations move the graph and its asymptote.

### Properties of Logarithmic Graphs

For function <InlineMath math="f(x) = \log_b x" /> with <InlineMath math="b>0,\ b\neq1" />:

1. **Domain**: <InlineMath math="x > 0" /> (positive numbers only)
2. Range: All real numbers (<InlineMath math="-\infty < y < \infty" />)
3. <InlineMath math="x" />-intercept: <InlineMath math="(1, 0)" /> because <InlineMath math="\log_b 1 = 0" />
4. **Vertical asymptote**: <InlineMath math="y" />-axis (<InlineMath math="x = 0" />)
5. Increasing for <InlineMath math="b > 1" />
6. Decreasing for <InlineMath math="0 < b < 1" />

## Drawing Logarithmic Function Graphs

Choose **powers of the base** as inputs. An input of <InlineMath math="b^n" /> has output <InlineMath math="n" />, so you obtain exact points without rounding.

Negative powers also give valid positive inputs. With base two, an input of one quarter gives an output of negative two.

<BlockMath math="2^{-2}=\frac14 \quad\Longleftrightarrow\quad \log_2\frac14=-2" />

## Transformations of Logarithmic Graphs

A **vertical shift** moves the whole curve and leaves the vertical asymptote at <InlineMath math="x = 0" />. A horizontal shift instead moves the asymptote together with the <InlineMath math="x" />-intercept to the right or left, so the whole graph moves sideways.

Add a constant **outside the logarithm** to move every output. The domain and vertical asymptote stay fixed, but the horizontal intercept satisfies <InlineMath math="\log_b x=-k" />, so <InlineMath math="x=b^{-k}" />.

### Domain and Asymptote

The logarithm is defined only when its argument is positive. The boundary of that condition gives the vertical asymptote:

- Domain: <InlineMath math="x + 3 > 0 \Rightarrow x > -3" />
- Range: All real numbers
- Vertical asymptote: <InlineMath math="x = -3" />

The boundary is excluded because a logarithm needs a **positive argument**, not zero. Negative two is allowed, but negative three makes the argument zero.

<BlockMath math="(-2)+3=1>0,\qquad (-3)+3=0" />

### A Four Unit Shift

Replacing <InlineMath math="x" /> with <InlineMath math="x-4" /> shifts the graph right. The same expression must also remain positive:

- Shift: <InlineMath math="4 \text{ units}" /> to the right
- Domain: <InlineMath math="x - 4 > 0 \Rightarrow x > 4" />

Check the horizontal intercept: input one on the original graph becomes input five. Its **output** remains zero.

<BlockMath math="\log_b(5-4)=\log_b1=0,\qquad b>0,\ b\ne1" />

### An Upward Shift

Adding <InlineMath math="2" /> outside the logarithm shifts every point vertically without changing the **domain** or the asymptote:

- Graph <InlineMath math="y = \log_3 x" /> shifted <InlineMath math="2 \text{ units}" /> up
- There is no <InlineMath math="y" />-intercept because the domain is <InlineMath math="x > 0" />

In particular, a <InlineMath math="y" />-intercept would require <InlineMath math="x=0" />, where the logarithm is undefined. The graph below confirms that it approaches but never reaches the <InlineMath math="y" />-axis.
