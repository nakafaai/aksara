## Sliding a Graph Left or Right

A **horizontal shift** by <InlineMath math="h" /> turns <InlineMath math="y = f(x)" /> into <InlineMath math="y = f(x - h)" />. Every point <InlineMath math="(x_0, y_0)" /> moves to <InlineMath math="(x_0 + h, y_0)" />, so **the height stays the same** and the whole graph slides sideways. For <InlineMath math="h > 0" /> the graph moves right, and for <InlineMath math="h < 0" /> it moves left. The first graph follows a parabola and its copy shifted three units to the right, so you can track the vertex as it travels.

<BlockMath math="(x_0, y_0) \longmapsto (x_0 + h,\ y_0)" />

The minus sign inside the bracket looks as if it should move the graph left, but it moves the graph right. The new function <InlineMath math="g(x) = f(x - 3)" /> reaches the output <InlineMath math="f(x_0)" /> only when its input is <InlineMath math="x_0 + 3" />, which is three units further right. The domain moves with the graph, while **the range stays the same**.

## The Domain and Intercepts Move With the Graph

The square root function <InlineMath math="f(x) = \sqrt{x}" /> needs <InlineMath math="x \ge 0" />, so its domain is <InlineMath math="[0, \infty)" />. Shift it four units to the left to get <InlineMath math="g(x) = \sqrt{x + 4}" />. The condition <InlineMath math="x + 4 \ge 0" /> gives <InlineMath math="x \ge -4" />, so **the new domain starts at** <InlineMath math="-4" />. The range stays <InlineMath math="[0, \infty)" />, because every value from zero upward is still reached.

The domain of <InlineMath math="f(x) - 3" /> stays the same, while its range moves down by three units.

## Common Mistakes With the Sign Inside the Bracket

Most errors come from treating **the input and the output** as if they were the same. The table lists five mistakes, why each one fails, and how to catch it.

| Mistake | Why it fails | How to catch it |
| --- | --- | --- |
| Reading <InlineMath math="x - 3" /> as a shift of three units to the left | The graph moves right, as the machine showed for <InlineMath math="g(8) = 11" /> | Check that the vertex of <InlineMath math="x^2" /> lands on <InlineMath math="(3, 0)" /> |
| Replacing only one <InlineMath math="x" /> | Every <InlineMath math="x" /> in the rule becomes <InlineMath math="x - 3" /> | Write <InlineMath math="2(x - 3) + 1" /> and not <InlineMath math="2x - 3 + 1" />, which equals <InlineMath math="2x - 2" /> |
| Writing <InlineMath math="f(x) - 3" /> for a horizontal shift | Subtracting outside the bracket moves the graph down | Ask whether the change happens to the input or to the output |
| Judging the direction with a straight line | A shifted line can equal a vertical shift of the original line | Compare a curve or one pair of corresponding points |
| Keeping the domain fixed | The domain moves by the same amount as the input shift | Solve the new input condition, such as <InlineMath math="x + 4 \ge 0" /> |

1. Shift <InlineMath math="f(x) = x^2 + 2x + 1" /> three units to the right. Write the new equation and find its vertex.
