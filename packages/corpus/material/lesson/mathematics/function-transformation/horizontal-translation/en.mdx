## Sliding a Graph Left or Right

Horizontal translation slides a function graph left or right along the <InlineMath math="x" />-axis without changing its shape. <Highlight>Every point moves by the same horizontal distance</Highlight>, as if the graph were an object sliding across a table.

If you have a function <InlineMath math="f(x)" />, then horizontal translation produces a new function <InlineMath math="g(x) = f(x - h)" /> where <InlineMath math="h" /> is the translation constant.

### Reading the Sign Rule

Look at where <InlineMath math="h" /> sits in the rule below. It is written inside the parentheses together with <InlineMath math="x" />, so it changes the input before the function runs.

<BlockMath math="g(x) = f(x - h)" />

To obtain the **same output** as the old input <InlineMath math="a" />, the new input must satisfy <InlineMath math="x-h=a" />. Thus <InlineMath math="x=a+h" />, explaining the shift without memorizing signs.

<BlockMath math="g(a+h)=f((a+h)-h)=f(a)" />

Because <InlineMath math="h" /> sits inside the parentheses, its sign works the <Highlight>opposite way from the direction you read</Highlight>. Subtracting a positive number from <InlineMath math="x" /> slides the graph right, while adding a positive number slides it left.

| Value of <InlineMath math="h" /> | Shift of the graph | Example of the vertex |
| --- | --- | --- |
| <InlineMath math="h > 0" /> | Right by <InlineMath math="h \text{ units}" /> | <InlineMath math="(0,0)" /> becomes <InlineMath math="(h,0)" /> |
| <InlineMath math="h < 0" /> | Left by <InlineMath math="\lvert h \rvert \text{ units}" /> | <InlineMath math="(0,0)" /> becomes <InlineMath math="(h,0)" /> |
| <InlineMath math="h = 0" /> | The graph does not move | <InlineMath math="(0,0)" /> stays where it is |

All three rows use the vertex <InlineMath math="(0,0)" /> as a reference so the direction is easy to compare. For a function with a different reference point, every point moves by the same distance in the same direction.

| <InlineMath math="(x+2)^2" /> | <InlineMath math="(-2,0)" /> | <InlineMath math="-2" /> |

## Checking the Rule on a Linear Graph

The **same rule** applies to the linear function <InlineMath math="f(x) = 2x + 1" />. On a straight line, a horizontal shift does not change the slope, so checking the sign is easier than on a parabola.

      }),
      smooth: false,
      color: "#d97706",

/>

The purple line is the original line with slope <InlineMath math="2" />. The orange line is <InlineMath math="g(x) = 2(x-4)+1" />, which shifts right by <InlineMath math="4 \text{ units}" />, and the blue line is <InlineMath math="h(x) = 2(x+3)+1" />, which shifts left by <InlineMath math="3 \text{ units}" />. All three lines stay parallel because the slope does not change.

In both examples the direction of the shift always comes from the sign inside the parentheses. That is the opposite of a vertical translation, which adds its constant outside the function.

## Which Values the Horizontal Shift Moves

Once you know the direction of the shift, you still need to know which parts of the function move with it. A horizontal translation acts on the input, so everything that depends on the position of <InlineMath math="x" /> moves, while the output values stay the same.

Take a point <InlineMath math="(a, b)" /> on the graph of <InlineMath math="f(x)" />. After a translation by <InlineMath math="h" />, that point moves to <InlineMath math="(a + h, b)" /> on the graph of <InlineMath math="f(x - h)" />. The <InlineMath math="y" /> value does not change, only the <InlineMath math="x" /> coordinate moves.

| Part of the function | Before the translation | After the translation by <InlineMath math="h" /> |
| --- | --- | --- |
| Graph shape | The original shape | The same shape, moved horizontally |
| Point <InlineMath math="(a, b)" /> | On the graph of <InlineMath math="f(x)" /> | Moves to <InlineMath math="(a + h, b)" /> |
| Domain <InlineMath math="[c, d]" /> | The original interval | Moves to <InlineMath math="[c + h, d + h]" /> |
| Range | The original output values | The same values as the original function |

The domain moves with the graph because it describes the allowed values of <InlineMath math="x" />, while the range stays the same because the height of the graph at each point is unchanged. A vertical translation swaps those roles, keeping the domain and moving the range.

The **output height stays the same** at each moved point, not at each fixed input. For example, <InlineMath math="g(a+h)=f(a)" />, although <InlineMath math="g(a)" /> generally differs from <InlineMath math="f(a)" />.

## Checking the Rule on an Exponential Graph

For an exponential curve, the **horizontal asymptote stays fixed**, while the vertical intercept is recalculated at zero input.

      points: Array.from({ length: 969 }, (_, pointIndex) => {
        const x = -4 + (pointIndex / 968) * 8;
        return { x, y: Math.pow(2, x - 2), z: 0 };
      }),
      color: "#059669",
      labels: [{ text: <InlineMath math="g(x)=2^{x-2}" />, offset: [0.5, 1, 0], at: 480 }],
      showPoints: false,
    },
    {
      smooth: false,
      points: Array.from({ length: 481 }, (_, pointIndex) => {
        const x = -4 + (pointIndex / 480) * 8;
        return { x, y: Math.pow(2, x + 1), z: 0 };
      }),
      color: "#e11d48",
      labels: [{ text: <InlineMath math="h(x)=2^{x+1}" />, offset: [0.5, 1, 0], at: 240 }],
      showPoints: false,
    },
  ]}
  showZAxis={false}
/>

The horizontal asymptote stays at <InlineMath math="y = 0" />, because a horizontal shift does not change how the curve behaves when <InlineMath math="x" /> grows very large or very small. The function <InlineMath math="g(x) = 2^{x-2}" /> shifts right by <InlineMath math="2 \text{ units}" />, while <InlineMath math="h(x) = 2^{x+1}" /> shifts left by <InlineMath math="1 \text{ unit}" />.

Recalculate the vertical intercept using **zero input**. The old point <InlineMath math="(0,f(0))" /> moves to <InlineMath math="(h,f(0))" /> and generally ceases to be a vertical intercept. The new intercept is <InlineMath math="(0,f(-h))" />, provided <InlineMath math="-h" /> is in the domain.

<BlockMath math="f(0)=1,\qquad g(0)=2^{-2}=\frac14,\qquad h(0)=2^1=2" />

## Telling Horizontal and Vertical Shifts Apart

Horizontal and [vertical translations](/en/subjects/mathematics/function-transformation/vertical-translation) both move a graph, but they act on different parts of the rule. That difference decides which coordinate changes.

| Property | Horizontal translation | Vertical translation |
| --- | --- | --- |
| Rule | <InlineMath math="g(x) = f(x - h)" /> | <InlineMath math="g(x) = f(x) + k" /> |
| Part that changes | The function input | The function **output** |
| Direction of the shift | Along the <InlineMath math="x" /> coordinate | Along the <InlineMath math="y" /> coordinate |
| Sign of the constant | Opposite to the direction you read | The same as the sign of <InlineMath math="k" /> |
| Domain and range | Domain moves, range stays | Domain stays, range moves |

The main difference is where the constant sits. A constant inside the parentheses changes the input, so the shift is horizontal and its sign works in reverse. A constant outside the parentheses changes the output, so the shift is vertical and its sign works as written.

A [horizontal dilation](/en/subjects/mathematics/function-transformation/horizontal-dilation) changes a graph’s width, while a [vertical dilation](/en/subjects/mathematics/function-transformation/vertical-dilation) changes the distance from the horizontal axis. Translation adds a fixed displacement. In [combined function transformations](/en/subjects/mathematics/function-transformation/combined-transformation-function), shifting before scaling can give a different final position from shifting after scaling.
