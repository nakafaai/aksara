## Multiplying the Input by a Number

A **horizontal dilation**, also called a horizontal stretch or compression, turns <InlineMath math="y = f(x)" /> into <InlineMath math="y = f(bx)" /> with <InlineMath math="b > 0" />. The input multiplier <InlineMath math="b" /> multiplies <InlineMath math="x" /> before the rule <InlineMath math="f" /> acts, so every point on the graph of <InlineMath math="f" /> moves sideways:

<BlockMath math="(x_0, y_0) \longmapsto \left(\frac{x_0}{b},\ y_0\right)" />

Heights stay the same, and only the distance to the <InlineMath math="y" />-axis is divided by <InlineMath math="b" />. For <InlineMath math="b > 1" />, the graph is **compressed toward the <InlineMath math="y" />-axis** to <InlineMath math="\frac{1}{b}" /> of its width, and for <InlineMath math="0 < b < 1" />, it is stretched away from the <InlineMath math="y" />-axis by the factor <InlineMath math="\frac{1}{b}" />. In the 3D layer view, you can turn a stack of graphs <InlineMath math="f(bx)" /> and watch the width shrink as <InlineMath math="b" /> grows.

Points on the <InlineMath math="y" />-axis stay put because <InlineMath math="\frac{0}{b} = 0" />, and a negative multiplier adds a reflection across the <InlineMath math="y" />-axis. Some problems give a scale factor <InlineMath math="s" /> instead of <InlineMath math="b" />: every <InlineMath math="x" />-coordinate is multiplied by <InlineMath math="s" />, so the equation is <InlineMath math="y = f\left(\frac{x}{s}\right)" /> with <InlineMath math="b = \frac{1}{s}" />.

Apply the rule to the parabola <InlineMath math="f(x) = x^2" /> with <InlineMath math="b = 2" /> and <InlineMath math="b = \frac{1}{2}" />.

## Why a Larger Multiplier Narrows the Graph

Take a point <InlineMath math="(x_0, y_0)" /> on the graph of <InlineMath math="f" />, so <InlineMath math="f(x_0) = y_0" />. The new function <InlineMath math="g(x) = f(bx)" /> multiplies its input by <InlineMath math="b" /> first. For <InlineMath math="g" /> to produce the same output, the product <InlineMath math="bx" /> has to equal <InlineMath math="x_0" />, which means <InlineMath math="x = \frac{x_0}{b}" />.

<BlockMath math="g\left(\frac{x_0}{b}\right) = f\left(b \cdot \frac{x_0}{b}\right) = f(x_0) = y_0" />

With <InlineMath math="b = 2" />, the output that <InlineMath math="f" /> reaches at <InlineMath math="x = 6" /> is already reached by <InlineMath math="g" /> at <InlineMath math="x = 3" />. **Every output appears at half the distance from the <InlineMath math="y" />-axis**, so the graph of <InlineMath math="g" /> is half as wide as the graph of <InlineMath math="f" />.

Now apply <InlineMath math="b = 2" /> to <InlineMath math="f(x) = x^2 - 4x" />. This function has zeros at <InlineMath math="x = 0" /> and <InlineMath math="x = 4" /> and its vertex at <InlineMath math="(2, -4)" />. Replace every <InlineMath math="x" /> with <InlineMath math="2x" />:

<BlockMath math="\begin{aligned} g(x) &= f(2x) \\ &= (2x)^2 - 4(2x) \\ &= 4x^2 - 8x \end{aligned}" />

Factoring <InlineMath math="4x^2 - 8x = 4x(x - 2)" /> gives the zeros <InlineMath math="x = 0" /> and <InlineMath math="x = 2" />, which are the zeros of <InlineMath math="f" /> divided by <InlineMath math="2" />. The vertex of <InlineMath math="g" /> is at <InlineMath math="x = \frac{8}{2 \cdot 4} = 1" />, where <InlineMath math="g(1) = 4 - 8 = -4" />. So the vertex <InlineMath math="(2, -4)" /> moves to <InlineMath math="(1, -4)" />: **the height stays**, and **the distance to the <InlineMath math="y" />-axis is halved**.

In a [vertical dilation](/en/subjects/mathematics/function-transformation/vertical-dilation), the height of a point is proportional to the factor, so the trace of a point across similar layers is a straight line. In a horizontal dilation, the <InlineMath math="x" />-coordinate is divided by <InlineMath math="b" />, and that division is what bends the trace.

## Scale Factor and Input Multiplier

Not every problem states the input multiplier. Some give a **scale factor** <InlineMath math="s" />: every <InlineMath math="x" />-coordinate is multiplied by <InlineMath math="s" /> while the <InlineMath math="y" />-coordinate stays. The point <InlineMath math="(x_0, y_0)" /> on the graph of <InlineMath math="f" /> moves to <InlineMath math="(s x_0, y_0)" />.

To find the equation, express the old coordinates through the new ones. From <InlineMath math="x = s x_0" /> you get <InlineMath math="x_0 = \frac{x}{s}" />, then substitute into <InlineMath math="y = f(x_0)" />:

<BlockMath math="y = f\left(\frac{x}{s}\right)" />

This is <InlineMath math="y = f(bx)" /> with <InlineMath math="b = \frac{1}{s}" />. So **multiplying the coordinates by <InlineMath math="s" /> is the same as dividing the input by <InlineMath math="s" />**. A scale factor of <InlineMath math="3" /> makes the graph three times as wide, with equation <InlineMath math="y = f\left(\frac{x}{3}\right)" />.

For example, multiply every <InlineMath math="x" />-coordinate on the graph of <InlineMath math="y = \sqrt{x}" /> by <InlineMath math="3" />. Replace <InlineMath math="x" /> with <InlineMath math="\frac{x}{3}" />:

<BlockMath math="g(x) = \sqrt{\frac{x}{3}}" />

Check with the point <InlineMath math="(4, 2)" /> on <InlineMath math="y = \sqrt{x}" />. It moves to <InlineMath math="(12, 2)" />, and indeed <InlineMath math="g(12) = \sqrt{\frac{12}{3}} = \sqrt{4} = 2" />. The domain stays <InlineMath math="[0, \infty)" /> because <InlineMath math="\frac{x}{3} \ge 0" /> exactly when <InlineMath math="x \ge 0" />.

In the 3D layer view, the graphs of <InlineMath math="y = \sqrt{\frac{x}{s}}" /> for <InlineMath math="s = 1" />, <InlineMath math="2" />, and <InlineMath math="3" /> sit at the depths <InlineMath math="z = s" />. On layer <InlineMath math="s" />, the point at height <InlineMath math="2" /> lies at <InlineMath math="x = 4s" />, so on layer <InlineMath math="s = 3" /> you find the point <InlineMath math="(12, 2)" /> that you just checked.

A [dilation](/en/subjects/mathematics/geometric-transformation/dilation) about the origin multiplies both coordinates by the same factor, so every angle keeps its size and the image is similar to the original shape. A horizontal dilation multiplies only the <InlineMath math="x" />-coordinate, so **angles on the graph can change**. The two legs of <InlineMath math="y = |x|" /> are perpendicular, while the legs of <InlineMath math="y = |2x| = 2|x|" /> have slopes <InlineMath math="2" /> and <InlineMath math="-2" />, so the angle at the vertex closes to about <InlineMath math="53^\circ" />.

## Which Features Move and Which Stay

For <InlineMath math="b > 0" />, **every feature set by an <InlineMath math="x" />-value is divided by <InlineMath math="b" />**, while every feature set by a height stays the same.

| Feature | In <InlineMath math="f(bx)" /> | Reason |
| --- | --- | --- |
| Point <InlineMath math="(x_0, y_0)" /> | <InlineMath math="\left(\frac{x_0}{b}, y_0\right)" /> | height kept, <InlineMath math="x" /> divided by <InlineMath math="b" /> |
| Zero <InlineMath math="x_0" /> | <InlineMath math="\frac{x_0}{b}" /> | a zero is an <InlineMath math="x" />-value |
| Domain <InlineMath math="[c, d]" /> | <InlineMath math="\left[\frac{c}{b}, \frac{d}{b}\right]" /> | the domain holds <InlineMath math="x" />-values |
| Vertical asymptote <InlineMath math="x = x_1" /> | <InlineMath math="x = \frac{x_1}{b}" /> | a vertical line is fixed by an <InlineMath math="x" />-value |
| Range | unchanged | the range holds heights |
| <InlineMath math="y" />-intercept | stays at <InlineMath math="(0, f(0))" /> | <InlineMath math="\frac{0}{b} = 0" /> |
| Horizontal asymptote <InlineMath math="y = y_1" /> | unchanged | a horizontal line is fixed by a height |

## A Negative Multiplier Adds a Reflection

The rule <InlineMath math="(x_0, y_0) \longmapsto \left(\frac{x_0}{b}, y_0\right)" /> still holds when <InlineMath math="b < 0" />. Dividing by a negative number flips the sign of the <InlineMath math="x" />-coordinate, so the graph is stretched or compressed by the factor <InlineMath math="\frac{1}{|b|}" /> and then **reflected across the <InlineMath math="y" />-axis**. For <InlineMath math="b = -1" />, only the [horizontal reflection](/en/subjects/mathematics/function-transformation/horizontal-reflection) <InlineMath math="y = f(-x)" /> remains.

For an even function, the reflection cannot be seen. For <InlineMath math="f(x) = x^2 + 1" /> and <InlineMath math="b = -2" />, <InlineMath math="f(-2x) = 4x^2 + 1 = f(2x)" />, so the graph is the same as after the compression alone. The point <InlineMath math="(2, 5)" /> still moves to the left side, to <InlineMath math="(-1, 5)" />, and the point <InlineMath math="(-1, 2)" /> moves to the right side, to <InlineMath math="\left(\frac{1}{2}, 2\right)" />.

The only value you cannot use is <InlineMath math="b = 0" />. With <InlineMath math="b = 0" />, every input becomes <InlineMath math="0" />, so <InlineMath math="f(0 \cdot x) = f(0)" /> for every <InlineMath math="x" />, and the graph collapses to the horizontal line <InlineMath math="y = f(0)" /> whenever <InlineMath math="f(0)" /> is defined. The rule <InlineMath math="\frac{x_0}{b}" /> breaks down too, because division by zero is undefined.

The reflection for <InlineMath math="b < 0" /> also swaps the order of the domain endpoints. If <InlineMath math="f" /> has domain <InlineMath math="[c, d]" /> and <InlineMath math="b < 0" />, the left endpoint of the new domain comes from the right endpoint of the old one:

<BlockMath math="[c, d] \longmapsto \left[\frac{d}{b},\ \frac{c}{b}\right]" />

Take <InlineMath math="h(x) = |x - 2|" /> with vertex <InlineMath math="(2, 0)" /> and apply <InlineMath math="b = -2" />:

<BlockMath math="\begin{aligned} H(x) &= h(-2x) \\ &= |-2x - 2| \\ &= 2\,|x + 1| \end{aligned}" />

The last step uses <InlineMath math="-2x - 2 = -2(x + 1)" /> and <InlineMath math="|-2| = 2" />. The vertex moves to <InlineMath math="\left(\frac{2}{-2}, 0\right) = (-1, 0)" />, and indeed <InlineMath math="H(-1) = 0" />. The point <InlineMath math="(4, 2)" /> moves to <InlineMath math="(-2, 2)" />: its distance to the <InlineMath math="y" />-axis is halved, and it lands on the other side. The <InlineMath math="y" />-intercept <InlineMath math="(0, 2)" /> stays because <InlineMath math="H(0) = 2 = h(0)" />.

For comparison, <InlineMath math="b = -1" /> gives <InlineMath math="h(-x) = |-x - 2| = |x + 2|" /> with vertex <InlineMath math="(-2, 0)" />. That graph is only reflected, so its width stays the same.

## Mistakes in Reading the Multiplier

To find a mistake like the ones in this table, take a point you already know, **compute its image on the graph of <InlineMath math="f(bx)" />**, and check that image against your answer.

| Mistake | Why it fails | How to check |
| --- | --- | --- |
| Reading <InlineMath math="f(2x)" /> as a graph twice as wide | The input is doubled, so each output appears at half the distance | A zero <InlineMath math="x_0" /> must become <InlineMath math="\frac{x_0}{2}" /> |
| Dividing heights, as in <InlineMath math="\left(x_0, \frac{y_0}{b}\right)" /> | The multiplier inside <InlineMath math="f" /> changes only the input | Substitute <InlineMath math="x = \frac{x_0}{b}" /> and confirm the output is <InlineMath math="y_0" /> |
| Writing <InlineMath math="f(3x)" /> for a scale factor of <InlineMath math="3" /> | A scale factor <InlineMath math="s" /> means <InlineMath math="b = \frac{1}{s}" /> | The point <InlineMath math="(x_0, y_0)" /> must become <InlineMath math="(3x_0, y_0)" /> |
| Reading <InlineMath math="f(2x - 6)" /> as a shift of <InlineMath math="6" /> units | <InlineMath math="2x - 6 = 2(x - 3)" />, so the shift is <InlineMath math="3" /> units | Factor the multiplier out of the parentheses first |
| Keeping the domain order when <InlineMath math="b < 0" /> | Dividing by a negative number reverses the order | The left endpoint of the new domain must be the smaller number |

The equation <InlineMath math="f(2x - 6) = f(2(x - 3))" /> means the graph is compressed by the factor <InlineMath math="\frac{1}{2}" /> and then shifted <InlineMath math="3" /> units right, so the point <InlineMath math="(x_0, y_0)" /> ends at <InlineMath math="\left(\frac{x_0}{2} + 3, y_0\right)" />. If you shift <InlineMath math="3" /> units right first and compress afterward, the equation becomes <InlineMath math="f(2x - 3)" />, and the same point ends at <InlineMath math="\left(\frac{x_0 + 3}{2}, y_0\right)" />. In [combined function transformations](/en/subjects/mathematics/function-transformation/combined-transformation-function), you read the order of the steps from the form of the equation, as you did when factoring <InlineMath math="f(2x - 6)" />.

**Problem 3**. The multiplier is <InlineMath math="b = -\frac{1}{2}" />, so the domain endpoints will swap. The value <InlineMath math="g(x)" /> is defined when the input <InlineMath math="-\frac{x}{2}" /> lies in the domain of <InlineMath math="f" />. Multiply the inequality by <InlineMath math="-2" /> and **reverse both inequality signs**:

<BlockMath math="\begin{aligned} -2 &\le -\frac{x}{2} \le 8 \\ 4 &\ge x \ge -16 \end{aligned}" />

The rule <InlineMath math="\left[\frac{d}{b}, \frac{c}{b}\right] = \left[\frac{8}{-1/2}, \frac{-2}{-1/2}\right] = [-16, 4]" /> gives the same interval. Check both endpoints: <InlineMath math="x = -16" /> gives the input <InlineMath math="8" />, and <InlineMath math="x = 4" /> gives the input <InlineMath math="-2" />. Both are exactly the endpoints of the domain of <InlineMath math="f" />, so the domain of <InlineMath math="g" /> is <InlineMath math="[-16, 4]" />.

**Problem 4**. Substitute the point <InlineMath math="(6, 8)" /> into <InlineMath math="g(x) = 2^{bx}" />:

<BlockMath math="\begin{aligned} 2^{6b} &= 8 = 2^3 \\ 6b &= 3 \\ b &= \tfrac{1}{2} \end{aligned}" />

The function <InlineMath math="2^t" /> is increasing, so <InlineMath math="2^{6b} = 2^3" /> holds only for <InlineMath math="6b = 3" />. Because <InlineMath math="0 < b < 1" />, the graph of <InlineMath math="y = 2^x" /> is stretched away from the <InlineMath math="y" />-axis by the factor <InlineMath math="\frac{1}{b} = 2" />: **every distance to the <InlineMath math="y" />-axis doubles**. Check: the point <InlineMath math="(3, 8)" /> on <InlineMath math="y = 2^x" /> moves to <InlineMath math="\left(\frac{3}{1/2}, 8\right) = (6, 8)" />, exactly the given point.
