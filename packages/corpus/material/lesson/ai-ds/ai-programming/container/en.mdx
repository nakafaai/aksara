## Choosing How to Store Several Values

Choose a collection according to how the program will **access and change its data**.

Some collections can contain objects of different types, but each type has its own rules. Dictionary keys and set members, for example, must remain hashable while they are in the collection. The collection type also determines whether its contents can change after creation.


Python provides five common built-in collections:

- A **string** stores an immutable sequence of characters
- A **list** stores an ordered sequence whose elements can change
- A **tuple** stores an ordered sequence whose positions cannot change
- A **dictionary** stores **key-value pairs**
- A **set** stores unique members without indices

## Python Lists

A list **preserves element order** and allows its contents to change. One list may contain values of different types, although a consistent element shape is usually easier to process.

Unlike a fixed-size low-level array, a Python list can grow and shrink. It stores references to Python objects, so mutating a nested object can be visible through every reference to that object.


### List Properties

Compare **order, mixed types, and mutability** when choosing a list. Ordered means that every element has a position. It does not mean that values are automatically sorted.

| Characteristic | Explanation | Example |
|---------------|-------------|---------|
| Ordered | Each element has a position | `[1, 2, 3]` is different from `[3, 2, 1]` |
| Heterogeneous | Can hold various data types | `[1, 'text', 3.14, True]` |
| Mutable | Contents can be changed after creation | Can add, remove, or modify elements |

## List Indexing

Indexing accesses one list element by its position. Python uses zero-based indexing, so the first element has index <InlineMath math="0" />.


Python list indices follow these rules:

- **Positive indices** start from <InlineMath math="0" /> for the first element
- **Negative indices** start from <InlineMath math="-1" /> for the last element
- **An index outside the valid range** raises `IndexError`

## Slicing with Stride

Slicing takes part of a list. The step sets the **distance between selected elements**.


The complete syntax is `list[start:stop:step]`, where:

- `start` is the first included index
- `stop` is the first excluded index
- `step` is the distance between selected indices

<CodeBlock
  data={[
    {
      language: "python",
      filename: "list_slicing.py",
      code: `# List for slicing examples
x = [0, 1, 2, 3, 4, 5]
print('x =', x)                              # Output: x = [0, 1, 2, 3, 4, 5]

# Basic slicing
print('x[1:4] =', x[1:4])                    # Output: x[1:4] = [1, 2, 3]

# Slicing from negative index to end
print('x[-3:] =', x[-3:])                    # Output: x[-3:] = [3, 4, 5]

# Slicing with step (stride)
print('x[1:4:2] =', x[1:4:2])                # Output: x[1:4:2] = [1, 3]

# Reversing list with negative step
print('x[::-1] =', x[::-1])                  # Output: x[::-1] = [5, 4, 3, 2, 1, 0]`
    }
  ]}
/>

Slicing selects a contiguous or regularly spaced part of a list. For `x = [0, 1, 2, 3, 4, 5]`, `x[1:4]` returns the elements at indices <InlineMath math="1" />, <InlineMath math="2" />, and <InlineMath math="3" />. The end index <InlineMath math="4" /> is excluded. The expression `x[1:4:2]` uses a step of <InlineMath math="2" />, so it selects indices <InlineMath math="1" /> and <InlineMath math="3" />.

The top row takes `x[1:4:2]`: it starts at index <InlineMath math="1" />, jumps two steps, and stops before index <InlineMath math="4" />, so the result is `[1, 3]`. The bottom row is `x[::-1]`. The step <InlineMath math="-1" /> reads from the back, and the teal lines show each element moving from position <InlineMath math="i" /> to position <InlineMath math="5-i" />. All the lines cross in the middle, right between elements <InlineMath math="2" /> and <InlineMath math="3" />.

## Common List Forms

A list can be empty, contain mixed types, or contain other lists:

1. **Empty Lists**

   Both `[]` and `list()` create an empty list that can be filled later.

2. **Heterogeneous Lists**

   One list can contain a name, an age, and a Boolean value. Use mixed types only when each position has a clear meaning.

3. **Nested Lists**

   A nested list contains other lists as its elements. Equal-length inner lists can represent rows of a matrix or table.

## Other Containers

Three other common containers have different rules about order, duplicates, and changes after creation. A tuple fixes its positions, a dictionary maps each unique key to one value, and a set keeps <Highlight>only unique items</Highlight> without promising an order.

### Tuple

A tuple resembles a list, but its **positions cannot be replaced** after creation. Several values can be packed into one tuple and later unpacked into separate variables.

A tuple cannot replace its own elements, but an element may refer to a mutable object whose contents can still change.

| Aspect | Tuple | List |
|-------|-------|------|
| **Mutability** | Immutable | Mutable |
| **Syntax** | `()` or without parentheses | `[]` |
| **Usage** | Data with fixed positions, such as coordinates | Data that needs additions or changes |

### Set

A set stores unique, hashable elements and supports mathematical set operations. It provides no element indices and makes **no iteration-order guarantee**. Nonempty set literals use `{}`, while an empty set must be created with `set()` because `{}` creates an empty dictionary.

### Collection Type Comparison

The four built-in collections differ in **order, mutability, and duplicate handling**. The table compares them so you can pick one from the task at hand.

| Container | Syntax | Ordered | Mutable | Duplicates | Main Usage |
|-----------|---------|---------|---------|------------|------------|
| **List** | `[1, 2, 3]` | Yes | Yes | Yes | Data that needs changing |
| **Tuple** | `(1, 2, 3)` | Yes | No | Yes | Fixed data, coordinates |
| **Dictionary** | `{'a': 1}` | Yes* | Yes | No (keys) | Key-value mapping |
| **Set** | `{1, 2, 3}` | No | Yes | No | Unique elements, set operations |

> Dictionary iteration preserves insertion order as a language guarantee since Python `3.7`. Updating an existing key keeps its position. Deleting and reinserting it places it at the end.
