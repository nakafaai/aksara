## Operator Precedence Order

Operator precedence <Highlight>determines how Python groups an expression when parentheses do not state the grouping explicitly</Highlight>. This rule describes the grouping. Python evaluates operands from left to right. Precedence determines how operations on those operands are grouped.

<Mermaid
  title="Precedence of the Operators Discussed"
  description="The diagram summarizes the precedence of the operators discussed, not the evaluation time of each operand."
  chart={`
    flowchart LR
        A["parentheses, calls, indexing"] --> B["** exponent"]
        B --> C["unary +, -, ~"]
        C --> D["*, /, //, %"]
        D --> E["+, -"]
        E --> F["comparison operators"]
        F --> G["not"]
        G --> H["and"]
        H --> I["or"]
  `}
/>

Exponentiation treats a unary operator on its right specially: `2 ** -1` means `2 ** (-1)` and equals `0.5`. By contrast, `-2 ** 2` means `-(2 ** 2)` and equals `-4`.

Higher-precedence operators bind more tightly. Most binary operators at the same level group from left to right, but exponentiation groups from right to left and comparisons form chains. Parentheses are the clearest choice whenever the intended grouping might be missed.

## Comparison Operators

Comparison operators are used to compare two values and produce boolean values (`True` or `False`). Comparison operators available in Python:

- `==` equal to
- `!=` not equal to
- `<` less than
- `<=` less than or equal to
- `>` greater than
- `>=` greater than or equal to

Comparisons of built-in values such as numbers and strings return **boolean values**. User-defined objects may implement other comparison results. Equality can compare objects of different types, but ordering comparisons such as `<` require types that define a compatible ordering and may raise `TypeError` otherwise. Comparisons share a precedence level and can be chained.

## Boolean Operators

Boolean operators combine multiple conditions or modify boolean values. Python provides three main boolean operators:

<Mermaid
  title="Boolean Operators Combine Decisions"
  description="See how and, or, and not combine true-false values in program decisions."
  chart={`
    flowchart LR
        A[Input A] --> AND{and}
        B[Input B] --> AND
        AND --> C["A false: A"]
        AND --> D["A true: B"]

        E[Input A] --> OR{or}
        F[Input B] --> OR
        OR --> G["A true: A"]
        OR --> H["A false: B"]

        I[Input] --> NOT{not}
        NOT --> J["Opposite boolean"]
  `}
/>

1. **Operator `and`** returns the first value if it's false, or the second value if the first value is true.

2. **Operator `or`** returns the first value if it's true, or the second value if the first value is false.

3. **Operator `not`** differs from `and` and `or` operators because it always produces a new boolean value.

<CodeBlock
  data={[
    {
      language: "python",
      filename: "boolean_operators.py",
      code: `# Example of boolean operators
>>> 4.0 and 5.0  # 4.0 is truthy, then returns 5.0 without truth-testing 5.0
5.0

>>> 0 and 5  # evaluates 0 as false, returns 0 (short-circuit)
0

>>> 4.0 or 5.0  # evaluates 4.0 as true, returns 4.0 (short-circuit)
4.0

>>> 0 or 5  # 0 is falsy, then returns 5 without truth-testing 5
5

>>> not 4.0  # evaluates 4.0 as true, returns False
False

>>> not 0  # evaluates 0 as false, returns True
True`
    }
  ]}
/>

The `and` and `or` operators use <Highlight>short-circuit evaluation</Highlight>, meaning evaluation stops when the result can be determined without evaluating all operands. Both return the last evaluated argument, while the `not` operator always creates a new boolean value.

## Values in Boolean Context

Any Python object can undergo **truth testing**, including objects that are not the values `True` and `False`. Python then decides for itself which values count as false. Under that rule an empty list, the number zero, and the empty string all behave like `False` inside an `if`, while a non-empty container behaves like `True`.

### Falsy and Truthy Values

<Mermaid
  title="Values Python Treats as Condition Results"
  description="Group the values Python treats as False or True before they are used in conditions."
  chart={`
    flowchart TD
        A[Python Values] --> B{Boolean Evaluation}
        B -->|Falsy| C[False]
        B -->|Falsy| D[None]
        B -->|Falsy| E["Zero and empty containers"]
        B -->|Truthy| F["Examples of truthy built-ins"]
        F --> G["Non-zero numbers"]
        F --> H["Non-empty values"]
  `}
/>

These built-in values follow **truthiness rules** that you can test with `bool()`.

| Group | Falsy examples | Truthy examples |
| --- | --- | --- |
| Boolean | `False` | `True` |
| Missing value | `None` | Not applicable |
| Numbers | `0`, `0.0`, `0j` | `-1`, `0.5`, `2j` |
| Strings | `""` | `"0"` |
| Containers | `[]`, `{}`, `()`, `set()` | `[0]`, `{"a": 0}` |

The string `"0"` and list `[0]` remain truthy because they are not empty. The value of an element does not determine the truthiness of its built-in container.

User-defined objects can customize truth testing with `__bool__()` or `__len__()`. If neither is defined, an instance is truthy by default.

## Floating Point Number Comparison

Many decimal fractions have no exact finite binary floating-point representation. Arithmetic rounds intermediate results, so two mathematically equivalent calculations can produce **nearby but unequal floats**.

### Solution with the Isclose Function

Python provides the `math.isclose(a, b, rel_tol=1e-09, abs_tol=0.0)` function to test approximate equality. This function uses **relative and absolute tolerances** through `rel_tol` and `abs_tol` to determine whether two values are close enough.


For `math.isclose(100, 95, rel_tol=0.05)`, the absolute difference is 5. Relative tolerance uses the larger absolute value, which is 100.

<BlockMath math="\begin{aligned} |100-95| &= 5 \\ 0.05\max(|100|,|95|) &= 5 \\ 5 &\leq \max(5,0) \end{aligned}" />

The difference does not exceed the tolerance, so the result is `True`. With `abs_tol=5`, the absolute tolerance of 5 also accepts this difference.


> Use exact equality when exact identity of the floating-point value is genuinely required. For measured or calculated quantities, choose tolerances from the problem domain and use `math.isclose()`. Near zero, relative tolerance alone shrinks with the compared values, so set an `abs_tol` that reflects the smallest meaningful difference.
