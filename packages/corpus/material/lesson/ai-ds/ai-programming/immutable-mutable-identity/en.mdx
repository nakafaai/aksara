## Lists and Mutability

In Python, lists are data structures that can be modified after they are created. A mutation changes an existing list. Assignment binds a name.

When a list is assigned to a variable, <Highlight>the variable refers to that list object</Highlight>. Assignment does not copy the list. Another variable or container can therefore refer to the very same object.

<CodeBlock
  data={[
    {
      language: "python",
      filename: "list_reference.py",
      code: `# Creating list and providing reference
list1 = [0, 1, 2]
list2 = ['a', list1, True]

print(list2)  # ['a', [0, 1, 2], True]

# Changing elements in list1
list1[1] = [3, 4, 5]
print(list2)  # ['a', [0, [3, 4, 5], 2], True]`
    }
  ]}
/>

Notice how changes to `list1` also affect `list2`. This happens because `list2` doesn't store a copy of `list1`, but rather a reference to the same list object in memory.

### A Full Slice Creates a Shallow Copy

A full slice creates a **new outer list** containing references to the same elements. This is a shallow copy. Replacing an outer element leaves the original list unchanged, while a nested mutable element remains shared.

<CodeBlock
  data={[
    {
      language: "python",
      filename: "slice_copy.py",
      code: `# Slice operations create new lists
list1 = [0, 1, 2]
list2 = list1[:]  # Taking all elements with slice

print(id(list1))  # Example: 3104
print(id(list2))  # Example: 8864 (different from list1)

# Changing elements in list2 doesn't affect list1
list2[0] = 'x'
print(list1)  # [0, 1, 2] (unchanged)
print(list2)  # ['x', 1, 2]

# Nested mutable elements are still shared by a shallow copy
nested1 = [[1], [2]]
nested2 = nested1[:]
nested2[0].append(3)
print(nested1)  # [[1, 3], [2]]`
    }
  ]}
/>

A list can change in place. Starting from `nums = [1, 2, 3]`, `nums[0] = 10` replaces the first element and `nums.append(4)` adds one at the end. The result is `[10, 2, 3, 4]`, and the list is still the same object.

## Object Identity Type and Value

Every Python object has three characteristics: **identity, type, and value**.

### Object Identity

Two references have the same identity when they point to the same object. `id()` returns an integer that is **unique among simultaneously living objects**, while `is` compares identity directly. The language does not promise that the integer is a physical memory address.

<CodeBlock
  data={[
    {
      language: "python",
      filename: "object_identity.py",
      code: `a = 300
print(a)          # 300
print(type(a))    # <class 'int'>
print(id(a))      # Example: 10120

b = a  # b references the same object as a
print(id(b))      # Example: 10120 (same as a)

a = a + 1  # Creates new object
print(id(a))      # Example: 10492 (different from before)`
    }
  ]}
/>

### Comparing Identity and Value

Use `is` when object identity is the question, most commonly in checks such as `value is None`. Use `==` **when values should be compared**. Interpreter caching and constant folding can make equal immutable values share an identity, but application logic must never rely on that implementation detail.

<CodeBlock
  data={[
    {
      language: "python",
      filename: "identity_comparison.py",
      code: `a = [1, 2]
b = a
c = [1, 2]

print(a is b)  # True: same object
print(a == b)  # True: same value
print(a is c)  # False: different objects
print(a == c)  # True: equal values`
    }
  ]}
/>

Run `a = [1, 2]`, `b = a`, `c = a.copy()`, then `b.append(3)`. This picture shows the result: `a` and `b` are two names for one list object, so `a` changes to `[1, 2, 3]` too and `a is b` is `True`. `c` points to another object that is still `[1, 2]`, so `a is c` is `False` even though their contents were once equal. Identity follows the segments, not the contents.

## Mutable and Immutable Objects

Python groups its objects by one question, which is whether the contents can change after the object exists. An immutable object such as an `int`, a `str`, or a `tuple` keeps the same value for its whole life, so an operation that looks like a change builds a new object instead. A mutable object such as a `list`, a `dict`, or a `set` holds contents that can change while the object itself stays the same one.

That difference matters as soon as two names refer to the same object, because <Highlight>every name sees the change</Highlight> when the object is mutable.

### Immutable Objects

Immutable objects **cannot be changed after creation**. Any operation that appears to change the object actually creates a new object.

<CodeBlock
  data={[
    {
      language: "python",
      filename: "immutable_objects.py",
      code: `# Integer is immutable
a = 300
print(id(a))  # Example: 10120

a = a + 1     # Creates new object
print(id(a))  # Example: 10492 (different)

# String is also immutable
str_var = 'hello'
print(id(str_var))  # Example: 75568

# Trying to change string will result in error
# str_var[1] = 'a'  # TypeError`
    }
  ]}
/>

Common immutable types in Python include:

- `bool` (boolean)
- `int` (integer)
- `float` (floating point)
- `complex` (complex numbers)
- `str` (string)
- `tuple` (tuple)

A tuple's own sequence of references cannot change, although an object referenced by the tuple can still be mutable.

### Mutable Objects

Mutable objects can be changed after creation without creating a new object. The **object's identity remains the same** even though its value changes.

<CodeBlock
  data={[
    {
      language: "python",
      filename: "mutable_objects.py",
      code: `# List is mutable
list_var = [0, 1, 2]
original = list_var
original_id = id(original)

# Changing an element preserves the list's identity
list_var[0] = 9
print(id(list_var) == original_id)  # True

# Assignment rebinds the variable to a new object
list_var = [0, 0, 0]
print(id(list_var) == original_id)  # False

# Slice assignment mutates the current list in place
current_id = id(list_var)
list_var[:] = ['a', 'b', 'c']
print(id(list_var) == current_id)  # True`
    }
  ]}
/>

Common mutable types in Python include:

- `list` (list)
- `dict` (dictionary)
- `set` (set)

### Assignment vs Modification Behavior

Assignment **binds a name to an object**, while in-place modification changes the existing object.

<CodeBlock
  data={[
    {
      language: "python",
      filename: "assignment_vs_modification.py",
      code: `list1 = [0, 1, 2]
list2 = list1  # Both variables reference the same object

print(id(list1))     # Example: 700
print(id(list2))     # Example: 700 (same)

# In-place modification affects both variables
list1[1] = 'x'
print(list1)         # [0, 'x', 2]
print(list2)         # [0, 'x', 2] (also changed)

# Assignment creates new reference
list1 = [1, 2, 3]
print(list1)         # [1, 2, 3]
print(list2)         # [0, 'x', 2] (unchanged)`
    }
  ]}
/>

Mutability determines whether an existing object can change. Assignment can rebind a name regardless of mutability. Immutability removes one source of shared-state bugs, but it does not by itself make a program thread-safe. Referenced mutable objects, compound operations, and external resources still require deliberate synchronization.

Compare `a = 5; b = a; a += 1` with `x = [5]; y = x; x[0] += 1`. Integers are immutable, so `a += 1` binds `a` to a new object `6` and `b` stays `5`. Lists are mutable, so `x[0] += 1` changes the object that `y` sees too.
