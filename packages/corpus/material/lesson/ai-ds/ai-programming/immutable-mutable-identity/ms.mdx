## Senarai dan Kebolehubahan

Dalam Python, senarai (list) ialah struktur data yang boleh diubah selepas ia dicipta. Mutasi mengubah senarai yang sedia ada. Umpukan pula mengikat nama.

Apabila senarai diumpukkan kepada pemboleh ubah, <Highlight>pemboleh ubah itu merujuk kepada objek senarai tersebut</Highlight>. Umpukan tidak menyalin senarai. Jadi, pemboleh ubah atau bekas lain boleh merujuk kepada objek yang sama itu juga.

<CodeBlock
  data={[
    {
      language: "python",
      filename: "list_reference.py",
      code: `# Cipta senarai dan beri rujukan
list1 = [0, 1, 2]
list2 = ['a', list1, True]

print(list2)  # ['a', [0, 1, 2], True]

# Ubah unsur dalam list1
list1[1] = [3, 4, 5]
print(list2)  # ['a', [0, [3, 4, 5], 2], True]`
    }
  ]}
/>

Perhatikan bahawa perubahan pada `list1` turut menjejaskan `list2`. Ini berlaku kerana `list2` tidak menyimpan salinan `list1`, sebaliknya menyimpan rujukan kepada objek senarai yang sama dalam memori.

### Hirisan Penuh Mencipta Salinan Cetek

Hirisan penuh mencipta **senarai luar yang baharu** yang mengandungi rujukan kepada unsur yang sama. Inilah salinan cetek (shallow copy). Menggantikan unsur luar tidak mengubah senarai asal, tetapi unsur boleh diubah yang bersarang masih dikongsi.

<CodeBlock
  data={[
    {
      language: "python",
      filename: "slice_copy.py",
      code: `# Operasi hirisan mencipta senarai baharu
list1 = [0, 1, 2]
list2 = list1[:]  # Ambil semua unsur dengan hirisan

print(id(list1))  # Contoh: 3104
print(id(list2))  # Contoh: 8864 (berbeza daripada list1)

# Mengubah unsur dalam list2 tidak menjejaskan list1
list2[0] = 'x'
print(list1)  # [0, 1, 2] (tidak berubah)
print(list2)  # ['x', 1, 2]

# Unsur boleh diubah yang bersarang masih dikongsi oleh salinan cetek
nested1 = [[1], [2]]
nested2 = nested1[:]
nested2[0].append(3)
print(nested1)  # [[1, 3], [2]]`
    }
  ]}
/>

Senarai boleh berubah di tempatnya. Bermula daripada `nums = [1, 2, 3]`, `nums[0] = 10` menggantikan unsur pertama dan `nums.append(4)` menambah satu unsur di hujung. Hasilnya ialah `[10, 2, 3, 4]`, dan senarai itu masih objek yang sama.

Setiap objek Python mempunyai tiga ciri: **identiti, jenis dan nilai**.

### Identiti Objek

Dua rujukan mempunyai identiti yang sama apabila kedua-duanya menunjuk kepada objek yang sama. `id()` memulangkan integer yang **unik dalam kalangan objek yang hidup pada masa yang sama**, manakala `is` membandingkan identiti secara terus. Bahasa Python tidak menjanjikan bahawa integer itu ialah alamat memori fizikal.

<CodeBlock
  data={[
    {
      language: "python",
      filename: "object_identity.py",
      code: `a = 300
print(a)          # 300
print(type(a))    # <class 'int'>
print(id(a))      # Contoh: 10120

b = a  # b merujuk kepada objek yang sama dengan a
print(id(b))      # Contoh: 10120 (sama dengan a)

a = a + 1  # Mencipta objek baharu
print(id(a))      # Contoh: 10492 (berbeza daripada sebelumnya)`
    }
  ]}
/>

### Membandingkan Identiti dan Nilai

Gunakan `is` apabila soalannya tentang identiti objek, paling kerap dalam semakan seperti `value is None`. Gunakan `==` **apabila nilai yang perlu dibandingkan**. Tembolok (cache) pentafsir dan lipatan pemalar (constant folding) boleh membuatkan nilai tidak boleh diubah yang sama berkongsi identiti, tetapi logik aplikasi tidak boleh sekali-kali bergantung pada butiran pelaksanaan itu.

<CodeBlock
  data={[
    {
      language: "python",
      filename: "identity_comparison.py",
      code: `a = [1, 2]
b = a
c = [1, 2]

print(a is b)  # True: objek yang sama
print(a == b)  # True: nilai yang sama
print(a is c)  # False: objek yang berbeza
print(a == c)  # True: nilainya sama`
    }
  ]}
/>

Jalankan `a = [1, 2]`, `b = a`, `c = a.copy()`, kemudian `b.append(3)`. Gambar ini menunjukkan hasilnya: `a` dan `b` ialah dua nama bagi satu objek senarai, jadi `a` juga berubah menjadi `[1, 2, 3]` dan `a is b` ialah `True`. `c` menunjuk kepada objek lain yang masih `[1, 2]`, jadi `a is c` ialah `False` walaupun kandungannya pernah sama. Identiti mengikut segmen, bukan kandungan.

## Objek Boleh Diubah dan Tidak Boleh Diubah

Python mengelompokkan objeknya berdasarkan satu soalan, iaitu sama ada kandungannya boleh berubah selepas objek itu wujud. Objek tidak boleh diubah (immutable) seperti `int`, `str` atau `tuple` mengekalkan nilai yang sama sepanjang hayatnya, jadi operasi yang nampak seperti mengubahnya sebenarnya membina objek baharu. Objek boleh diubah (mutable) seperti `list`, `dict` atau `set` memegang kandungan yang boleh berubah, sementara objek itu sendiri kekal objek yang sama.

Perbezaan ini penting sebaik sahaja dua nama merujuk kepada objek yang sama, kerana <Highlight>setiap nama nampak perubahan itu</Highlight> apabila objek tersebut boleh diubah.

### Objek Tidak Boleh Diubah

Objek jenis ini **tidak dapat diubah selepas dicipta**. Sebarang operasi yang nampak seperti mengubah objek itu sebenarnya mencipta objek baharu.

<CodeBlock
  data={[
    {
      language: "python",
      filename: "immutable_objects.py",
      code: `# Integer tidak boleh diubah
a = 300
print(id(a))  # Contoh: 10120

a = a + 1     # Mencipta objek baharu
print(id(a))  # Contoh: 10492 (berbeza)

# Rentetan juga tidak boleh diubah
str_var = 'hello'
print(id(str_var))  # Contoh: 75568

# Cubaan mengubah rentetan akan menghasilkan ralat
# str_var[1] = 'a'  # TypeError`
    }
  ]}
/>

Jenis tidak boleh diubah yang biasa dalam Python termasuk:

- `bool` (boolean)
- `int` (integer)
- `float` (titik apungan)
- `complex` (nombor kompleks)
- `str` (rentetan)
- `tuple` (tuple)

Jujukan rujukan milik tuple itu sendiri tidak boleh berubah, tetapi objek yang dirujuk oleh tuple itu masih boleh menjadi objek yang boleh diubah.

### Objek Boleh Diubah

Objek jenis ini boleh diubah selepas dicipta tanpa perlu mencipta objek baharu. **Identiti objek itu kekal sama** walaupun nilainya berubah.

<CodeBlock
  data={[
    {
      language: "python",
      filename: "mutable_objects.py",
      code: `# Senarai boleh diubah
list_var = [0, 1, 2]
original = list_var
original_id = id(original)

# Mengubah satu unsur mengekalkan identiti senarai
list_var[0] = 9
print(id(list_var) == original_id)  # True

# Umpukan mengikat semula pemboleh ubah kepada objek baharu
list_var = [0, 0, 0]
print(id(list_var) == original_id)  # False

# Umpukan hirisan mengubah senarai semasa di tempatnya
current_id = id(list_var)
list_var[:] = ['a', 'b', 'c']
print(id(list_var) == current_id)  # True`
    }
  ]}
/>

Jenis boleh diubah yang biasa dalam Python termasuk:

- `list` (senarai)
- `dict` (kamus)
- `set` (set)

### Umpukan berbanding Pengubahsuaian

Umpukan **mengikat nama kepada objek**, manakala pengubahsuaian di tempat mengubah objek yang sedia ada.

<CodeBlock
  data={[
    {
      language: "python",
      filename: "assignment_vs_modification.py",
      code: `list1 = [0, 1, 2]
list2 = list1  # Kedua-dua pemboleh ubah merujuk kepada objek yang sama

print(id(list1))     # Contoh: 700
print(id(list2))     # Contoh: 700 (sama)

# Pengubahsuaian di tempat menjejaskan kedua-dua pemboleh ubah
list1[1] = 'x'
print(list1)         # [0, 'x', 2]
print(list2)         # [0, 'x', 2] (turut berubah)

# Umpukan mencipta rujukan baharu
list1 = [1, 2, 3]
print(list1)         # [1, 2, 3]
print(list2)         # [0, 'x', 2] (tidak berubah)`
    }
  ]}
/>

Kebolehubahan menentukan sama ada objek yang sedia ada boleh berubah. Umpukan boleh mengikat semula nama tanpa mengira kebolehubahan. Sifat tidak boleh diubah menghapuskan satu punca pepijat keadaan kongsi, tetapi sifat itu sahaja tidak menjadikan atur cara selamat untuk bebenang (thread-safe). Objek boleh diubah yang dirujuk, operasi majmuk dan sumber luaran masih memerlukan penyegerakan yang dirancang dengan teliti.

Bandingkan `a = 5; b = a; a += 1` dengan `x = [5]; y = x; x[0] += 1`. Integer tidak boleh diubah, jadi `a += 1` mengikat `a` kepada objek baharu `6` dan `b` kekal `5`. Senarai boleh diubah, jadi `x[0] += 1` mengubah objek yang turut dilihat oleh `y`.
