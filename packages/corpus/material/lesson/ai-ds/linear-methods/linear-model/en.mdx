## What linear means here

A linear model relates a known input <InlineMath math="t \in \mathbb{R}^k" /> to an observed response <InlineMath math="y \in \mathbb{R}^d" /> through unknown parameters <InlineMath math="x \in \mathbb{R}^n" />:

<BlockMath math="y=h(t)x,\qquad h(t)\in\mathbb{R}^{d\times n}" />

The important word is **linear in the parameters**. For fixed <InlineMath math="t" />, the map from <InlineMath math="x" /> to <InlineMath math="y" /> is linear. The dependence on <InlineMath math="t" /> may contain powers, logarithms, sines, or other nonlinear basis functions.

This distinction prevents a common misconception: a linear model does not have to draw a straight line as a function of its input. It has to combine the unknown parameters linearly.

## From measurements to a design matrix

Suppose we collect <InlineMath math="M" /> input-response pairs <InlineMath math="(t_i,y_i)" /> and model each observation as

<BlockMath math="y_i=h(t_i)x+\varepsilon_i,\qquad i=1,\ldots,M" />

where <InlineMath math="\varepsilon_i" /> contains measurement noise and model mismatch. Stacking all responses and model blocks gives

<MathContainer>
<BlockMath math="b=\begin{pmatrix}y_1\\\vdots\\y_M\end{pmatrix}\in\mathbb{R}^{Md}" />
<BlockMath math="A=\begin{pmatrix}h(t_1)\\\vdots\\h(t_M)\end{pmatrix}\in\mathbb{R}^{Md\times n}" />
<BlockMath math="b=Ax+\varepsilon" />
</MathContainer>

The matrix <InlineMath math="A" /> is the **design matrix**. When the observations do not satisfy one parameter vector exactly, estimate <InlineMath math="x" /> with a least-squares or another residual model. Whether the parameters can be identified also depends on the rank and conditioning of <InlineMath math="A" />.

## Basis functions create many model shapes

Let <InlineMath math="\phi_1(t),\ldots,\phi_n(t)" /> be known basis functions. A scalar-response model can be written as

<BlockMath math="y(t)=\sum_{j=1}^{n}x_j\phi_j(t)=\begin{pmatrix}\phi_1(t)&\cdots&\phi_n(t)\end{pmatrix}x" />

Different choices of basis functions create different shapes while preserving linearity in <InlineMath math="x" />.

| Model | Basis representation |
| --- | --- |
| Affine line | <InlineMath math="y=a+bt=\begin{pmatrix}1&t\end{pmatrix}\begin{pmatrix}a\\b\end{pmatrix}" /> |
| Polynomial of degree <InlineMath math="p" /> | <InlineMath math="y=\sum_{j=0}^{p}a_jt^j=\begin{pmatrix}1&t&\cdots&t^p\end{pmatrix}\begin{pmatrix}a_0\\a_1\\\vdots\\a_p\end{pmatrix}" /> |
| Fourier basis | <InlineMath math="y=a_0+\sum_{j=1}^{p}\bigl(a_j\cos(jt)+b_j\sin(jt)\bigr)" /> |
| Two-input interaction | <InlineMath math="y=a+bt+cs+dts=\begin{pmatrix}1&t&s&ts\end{pmatrix}\begin{pmatrix}a\\b\\c\\d\end{pmatrix}" /> |

Terms such as <InlineMath math="t^p" />, <InlineMath math="\sin(jt)" />, and <InlineMath math="ts" /> may be nonlinear in the inputs. They are known coefficients once the inputs are observed, so the model remains linear in its unknown parameters.

## Multiple responses

If every input produces several responses, place their parameter vectors in a matrix <InlineMath math="B" />. For a row of basis values <InlineMath math="\phi(t)^{\mathsf T}" />,

<BlockMath math="y(t)^{\mathsf T}=\phi(t)^{\mathsf T}B" />

Each column of <InlineMath math="B" /> describes one response. This is still a linear model because every output is a linear combination of the same known basis values.

## Physical example: the ideal gas law

For an ideal gas,

<BlockMath math="pV=nRT" />

so at known temperature <InlineMath math="T" /> and volume <InlineMath math="V" />,

<BlockMath math="p=\frac{RT}{V}n" />

Pressure <InlineMath math="p" /> is linear in the unknown amount of substance <InlineMath math="n" />, measured in moles. The quantity <InlineMath math="n" /> is not itself the number of molecules; the number of specified entities is <InlineMath math="N=nN_A" />.

Repeated pressure measurements at several known <InlineMath math="(T_i,V_i)" /> values yield one design-matrix row <InlineMath math="RT_i/V_i" /> per observation.

## Local linearization of a nonlinear model

A genuinely nonlinear parameter model has the form

<BlockMath math="y=g(t,x)" />

where parameters may occur inside exponentials, powers, or products with one another. Near a current parameter value <InlineMath math="x_0" />, a first-order Taylor approximation gives

<BlockMath math="g(t,x)\approx g(t,x_0)+J_xg(t,x_0)(x-x_0)" />

The Jacobian <InlineMath math="J_xg(t,x_0)" /> is known after choosing <InlineMath math="x_0" />, so the correction <InlineMath math="x-x_0" /> appears linearly. This approximation is local, not an exact conversion of the nonlinear model. Iterative methods such as Gauss-Newton repeatedly update the linearization point.

## Checks before fitting

Before interpreting fitted parameters, verify that:

- the design matrix columns represent the intended basis functions and units
- the data contain enough independent information for the parameters, typically <InlineMath math="\operatorname{rank}(A)=n" />
- feature scales and the condition number do not make the solve numerically fragile
- the chosen residual loss matches the noise and outlier assumptions
- a local linearization is checked again against the original nonlinear model

A flexible basis can fit many shapes, but flexibility alone does not guarantee identifiability, numerical stability, or useful predictions.
