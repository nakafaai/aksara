## Repeated Basis Changes Preserve the Eigenvalues

The <InlineMath math="\mathrm{QR}" /> algorithm computes all eigenvalues of a square matrix through repeated changes of basis. Each step produces a <Highlight>similar matrix</Highlight>, so the eigenvalues stay the same. The iteration aims for a diagonal or Schur form, where eigenvalues are read from diagonal entries or small diagonal blocks. Convergence requires suitable shift and deflation strategies.

The version below is the unshifted <InlineMath math="\mathrm{QR}" /> iteration. Production eigensolvers also use shifts, reduce the matrix to Hessenberg form, and deflate converged blocks to improve speed and numerical reliability.

## One QR Iteration

For the deflation test below, first reduce the matrix by unitary similarity to **upper Hessenberg form**, whose entries below the first subdiagonal are zero. Start the iteration with that matrix. In the 2×2 example below, this condition already holds.

1. Start with <InlineMath math="A_0=A" />.

2. Factor the current matrix into a unitary or orthogonal factor <InlineMath math="Q_k" /> and an upper triangular factor <InlineMath math="R_k" />:

   <BlockMath math="A_k=Q_kR_k" />

3. Reverse the order of the factors to obtain the next iterate:

   <BlockMath math="A_{k+1}=R_kQ_k" />

4. Repeat the factorization and reverse multiplication. A small subdiagonal entry can be set to zero when it is negligible relative to its neighboring diagonal entries. That split, called **deflation**, isolates a converged eigenvalue or block.

   <BlockMath math="\begin{aligned} &amp;|(A_k)_{j+1,j}| \\ &amp;\leq \tau\left(|(A_k)_{j,j}|+|(A_k)_{j+1,j+1}|\right) \end{aligned}" />

Here <InlineMath math="\tau" /> is a tolerance chosen for the numerical precision and scale of the problem. Merely observing small changes in the diagonal is not a sufficient stopping test because the matrix can still have significant entries below the diagonal.

## Why the Eigenvalues Stay the Same

Because <InlineMath math="Q_k" /> is unitary, <InlineMath math="Q_k^{*}Q_k=I" />. Substituting <InlineMath math="R_k=Q_k^{*}A_k" /> into the reverse product gives

<MathContainer>
<BlockMath math="A_{k+1}=R_kQ_k" />
<BlockMath math="A_{k+1}=Q_k^{*}A_kQ_k" />
</MathContainer>

<InlineMath math="A_{k+1}" /> is unitarily similar to <InlineMath math="A_k" />. <Highlight>Similar matrices have the same characteristic polynomial</Highlight> and therefore the same eigenvalues. Each <InlineMath math="\mathrm{QR}" /> step expresses the same linear transformation in new coordinates.

## What the Iteration Converges To

The final form depends on the matrix and the **number system** used.

| Matrix | Converged form | How to read the eigenvalues |
|---|---|---|
| Real symmetric or complex Hermitian | Diagonal matrix | The diagonal entries are the real eigenvalues |
| General complex | Upper triangular Schur form | The diagonal entries are the eigenvalues |
| General real | Quasi-upper-triangular real Schur form | Each <InlineMath math="1\times1" /> block gives a real eigenvalue. Each <InlineMath math="2\times2" /> block gives a complex-conjugate pair |

The eigenvalues can appear in any order. Repeated values and special arrangements need separate handling because a strict magnitude ordering does not cover them.

Unshifted iteration does **not always converge to the listed form**. For example, the symmetric matrix below admits <InlineMath math="Q=C" /> and <InlineMath math="R=I" />, so the next iterate is unchanged:

<BlockMath math="C=\begin{pmatrix}0&1\\1&0\end{pmatrix},\qquad C=CI,\qquad RQ=IC=C" />

Its eigenvalues are 1 and −1. Their equal magnitudes show why practical algorithms need appropriate shifts and convergence checks.

## Worked Symmetric Example

Consider the symmetric matrix

<BlockMath math="A_0=\begin{pmatrix}2&1\\1&2\end{pmatrix}" />

One <InlineMath math="\mathrm{QR}" /> factorization and reverse multiplication give

<MathContainer>
<BlockMath math="\begin{aligned} &amp;Q_0=\frac{1}{\sqrt5}\begin{pmatrix}2&amp;-1\\1&amp;2\end{pmatrix}, \\ &amp;R_0=\begin{pmatrix}\sqrt5&amp;\frac4{\sqrt5}\\0&amp;\frac3{\sqrt5}\end{pmatrix} \end{aligned}" />
<BlockMath math="A_1=R_0Q_0=\begin{pmatrix}\frac{14}{5}&\frac35\\\frac35&\frac65\end{pmatrix}" />
</MathContainer>

The **off-diagonal magnitude** has already fallen from <InlineMath math="1" /> to <InlineMath math="3/5" />. Further iterations drive both off-diagonal entries toward zero:

<BlockMath math="A_k\longrightarrow\begin{pmatrix}3&0\\0&1\end{pmatrix}" />

The limiting diagonal contains the eigenvalues <InlineMath math="3" /> and <InlineMath math="1" />. Every iterate is similar to <InlineMath math="A_0" />, so these values belong to the original matrix.

Each step <InlineMath math="A_{k+1}=Q_k^TA_kQ_k" /> only rotates the ellipse <InlineMath math="x^TA_kx=1" />, because <InlineMath math="Q_k" /> is orthogonal. Zoom into the scene below: every ellipse has the same semiaxes <InlineMath math="1/\sqrt3" /> and <InlineMath math="1" />, so the eigenvalues stay <InlineMath math="3" /> and <InlineMath math="1" />. Only the direction changes. The ellipse of <InlineMath math="A_0" /> is tilted by <InlineMath math="45^\circ" />, then <InlineMath math="A_1" /> and <InlineMath math="A_2" /> line up closer to the axes, until the limit <InlineMath math="\operatorname{diag}(3,1)" /> sits on the axes and its eigenvalues can be read from the diagonal.

  cameraTarget={[0, 0, 0]}
  data={(() => {
    const step = ([[a, b], [c, d]]) => {
      const n = Math.hypot(a, c);
      const q1 = [a / n, c / n];
      const r12 = q1[0] * b + q1[1] * d;
      const u = [b - r12 * q1[0], d - r12 * q1[1]];
      const r22 = Math.hypot(u[0], u[1]);
      const q2 = [u[0] / r22, u[1] / r22];
      return [
        [n * q1[0] + r12 * q1[1], n * q2[0] + r12 * q2[1]],
        [r22 * q1[1], r22 * q2[1]],
      ];
    };
    const a0 = [[2, 1], [1, 2]];
    const a1 = step(a0);
    const a2 = step(a1);
    const ellipse = ([[a, b], [, d]]) =>
      Array.from({ length: 361 }, (_, index) => {
        const phi = (index / 360) * 2 * Math.PI;
        const radius = 1 / Math.sqrt(a * Math.cos(phi) ** 2 + 2 * b * Math.cos(phi) * Math.sin(phi) + d * Math.sin(phi) ** 2);
        return { x: radius * Math.cos(phi), y: radius * Math.sin(phi), z: 0 };
      });
    return [
      { points: ellipse(a0), color: "#64748b", smooth: false, showPoints: false, labels: [{ text: <InlineMath math="A_0" />, at: 135, offset: [-0.25, 0.2, 0] }] },

      { points: ellipse(a2), color: "#bb6800", smooth: false, showPoints: false, labels: [{ text: <InlineMath math="A_2" />, at: 276, offset: [-0.3, -0.3, 0] }] },
      { points: ellipse([[3, 0], [0, 1]]), color: "#c026d3", smooth: false, showPoints: false, labels: [{ text: <InlineMath math="A_\infty" />, at: 90, offset: [0.3, 0.2, 0] }] },
    ];
  })()}
