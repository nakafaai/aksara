## The factorization

<InlineMath math="\mathrm{LU}" /> decomposition stores Gaussian elimination as two triangular matrices. With partial pivoting, a nonsingular square matrix <InlineMath math="A \in \mathbb{R}^{n\times n}" /> is factored as

<BlockMath math="PA=LU" />

The three factors have the following roles:

- <InlineMath math="P" /> is a permutation matrix that records row swaps
- <InlineMath math="L" /> is unit lower triangular
- <InlineMath math="U" /> is upper triangular

At elimination step <InlineMath math="k" />, partial pivoting selects the largest-magnitude entry in column <InlineMath math="k" /> at or below the diagonal. This <Highlight>avoids dividing by a zero pivot</Highlight> and usually limits numerical error growth.

For a permutation matrix, <InlineMath math="P^{-1}=P^{\mathsf T}" />. The equality <InlineMath math="P^{-1}=P" /> holds only for special permutations, such as a single row swap, and is not true for every accumulated permutation.

## How elimination builds the factors

After selecting the pivot in column <InlineMath math="k" />, eliminate each entry below it with the multiplier

<BlockMath math="\ell_{ik}=\frac{u_{ik}}{u_{kk}},\qquad i=k+1,\ldots,n" />

Then apply the following row update.

<BlockMath math="\begin{aligned} &amp;u_{ij}\leftarrow u_{ij}-\ell_{ik}u_{kj}, \\ &amp;j=k,\ldots,n \end{aligned}" />

The multipliers are stored below the diagonal of <InlineMath math="L" />. If two rows are swapped after earlier elimination steps, the **already-filled columns** of <InlineMath math="L" /> must be swapped as well. Otherwise <InlineMath math="PA=LU" /> will no longer hold.

## Factoring a Matrix with Partial Pivoting

We will track **both row swaps** so the final permutation agrees with the factors.

<MathContainer>
<BlockMath math="A=\begin{pmatrix}0&2&1\\1&1&0\\2&1&1\end{pmatrix}" />
<BlockMath math="b=\begin{pmatrix}7\\3\\7\end{pmatrix}" />
</MathContainer>

### First pivot

The largest entry in the first column has magnitude <InlineMath math="2" />. **Swap rows one and three**, then eliminate the entry in row two with multiplier <InlineMath math="\ell_{21}=1/2" />. Row three already starts with zero.

<BlockMath math="\begin{pmatrix}2&amp;1&amp;1\\1&amp;1&amp;0\\0&amp;2&amp;1\end{pmatrix}\longrightarrow\begin{pmatrix}2&amp;1&amp;1\\0&amp;1/2&amp;-1/2\\0&amp;2&amp;1\end{pmatrix}" />

### Second pivot

The next pivot has magnitude <InlineMath math="2" /> in row three, so **swap rows two and three**. Swap their already stored first-column multipliers in <InlineMath math="L" /> as well. The multiplier for the final row is then <InlineMath math="\ell_{32}=(1/2)/2=1/4" />.

<BlockMath math="u_{33}=-\frac12-\frac14\cdot1=-\frac34" />

The resulting factors are

<MathContainer>
<BlockMath math="P=\begin{pmatrix}0&0&1\\1&0&0\\0&1&0\end{pmatrix}" />
<BlockMath math="L=\begin{pmatrix}1&0&0\\0&1&0\\\frac12&\frac14&1\end{pmatrix}" />
<BlockMath math="U=\begin{pmatrix}2&1&1\\0&2&1\\0&0&-\frac34\end{pmatrix}" />
</MathContainer>

Multiplying the factors verifies the decomposition:

<BlockMath math="LU=\begin{pmatrix}2&1&1\\0&2&1\\1&1&0\end{pmatrix}=PA" />

## Solving a linear system

From <InlineMath math="PA=LU" />, the equation <InlineMath math="Ax=b" /> becomes

<BlockMath math="LUx=Pb" />

We solve this system in **two stages** using triangular matrices.

### Forward substitution

First solve <InlineMath math="Ly=Pb" />. Here,

<MathContainer>
<BlockMath math="Pb=\begin{pmatrix}7\\7\\3\end{pmatrix}" />
<BlockMath math="y=\begin{pmatrix}7\\7\\-\frac94\end{pmatrix}" />
</MathContainer>

For a general lower triangular matrix,

<BlockMath math="\begin{aligned} &amp;y_i=\frac{1}{\ell_{ii}}\left(c_i-\sum_{j=1}^{i-1}\ell_{ij}y_j\right), \\ &amp;c=Pb \end{aligned}" />

The **diagonal entries** of this <InlineMath math="L" /> are all one.

### Backward substitution

Then solve <InlineMath math="Ux=y" /> from the **last row upward**:

<BlockMath math="x_i=\frac{1}{u_{ii}}\left(y_i-\sum_{j=i+1}^{n}u_{ij}x_j\right)" />

For the example,

<BlockMath math="x=\begin{pmatrix}1\\2\\3\end{pmatrix}" />

Direct substitution confirms <InlineMath math="Ax=b" />.

## Cost and reuse

Dense <InlineMath math="\mathrm{LU}" /> factorization requires approximately

<BlockMath math="\frac{2}{3}n^3+O(n^2)" />

This count gives the number of floating-point operations when multiplications and subtractions are counted separately. Once the factors are available, each new right-hand side requires only <InlineMath math="O(n^2)" /> work for the two substitutions. **Reusing the same** <InlineMath math="\mathrm{LU}" /> factors therefore avoids repeating the <InlineMath math="O(n^3)" /> factorization for every right-hand side.

The determinant also follows from the factors:

<BlockMath math="\det(A)=\det(P)\prod_{i=1}^{n}u_{ii}" />

## NumPy Implementation with Pivot Checks

<CodeBlock data={[{
  language: "python",
  filename: "plu_solve.py",
  code: `import numpy as np


def plu_factor(matrix, tolerance=1e-12):
    """Return P, L, U such that P @ matrix == L @ U."""
    A = np.asarray(matrix)
    if np.iscomplexobj(A):
        raise ValueError("this example requires real entries")
    A = A.astype(float)
    if A.ndim != 2 or A.shape[0] != A.shape[1] or A.shape[0] == 0:
        raise ValueError("PLU factorization requires a nonempty square matrix")
    if not np.all(np.isfinite(A)):
        raise ValueError("matrix entries must be finite")
    if not np.isfinite(tolerance) or tolerance < 0:
        raise ValueError("relative tolerance must be finite and nonnegative")
    threshold = tolerance * np.linalg.norm(A, ord=np.inf)

    n = A.shape[0]
    U = A.copy()
    L = np.eye(n)
    P = np.eye(n)

    for k in range(n - 1):
        pivot = k + np.argmax(np.abs(U[k:, k]))
        if abs(U[pivot, k]) <= threshold:
            raise np.linalg.LinAlgError("matrix is singular to working precision")

        if pivot != k:
            U[[k, pivot]] = U[[pivot, k]]
            P[[k, pivot]] = P[[pivot, k]]
            L[[k, pivot], :k] = L[[pivot, k], :k]

        for i in range(k + 1, n):
            L[i, k] = U[i, k] / U[k, k]
            U[i, k:] -= L[i, k] * U[k, k:]

    if abs(U[-1, -1]) <= threshold:
        raise np.linalg.LinAlgError("matrix is singular to working precision")

    return P, L, U


def forward_substitution(L, right_hand_side):
    b = np.asarray(right_hand_side, dtype=float)
    y = np.empty_like(b)
    for i in range(len(b)):
        y[i] = (b[i] - L[i, :i] @ y[:i]) / L[i, i]
    return y


def backward_substitution(U, right_hand_side, tolerance=1e-12):
    y = np.asarray(right_hand_side, dtype=float)
    x = np.empty_like(y)
    threshold = tolerance * np.linalg.norm(U, ord=np.inf)
    for i in range(len(y) - 1, -1, -1):
        if abs(U[i, i]) <= threshold:
            raise np.linalg.LinAlgError("singular triangular system")
        x[i] = (y[i] - U[i, i + 1:] @ x[i + 1:]) / U[i, i]
    return x


def plu_solve(matrix, right_hand_side):
    P, L, U = plu_factor(matrix)
    b = np.asarray(right_hand_side)
    if np.iscomplexobj(b):
        raise ValueError("this example requires a real right-hand side")
    b = b.astype(float)
    if b.shape != (len(P),) or not np.all(np.isfinite(b)):
        raise ValueError("right-hand side must be a finite vector of matching size")
    y = forward_substitution(L, P @ b)
    x = backward_substitution(U, y)
    return x, P, L, U


A = np.array([[0, 2, 1], [1, 1, 0], [2, 1, 1]], dtype=float)
b = np.array([7, 3, 7], dtype=float)
x, P, L, U = plu_solve(A, b)

assert np.allclose(P @ A, L @ U)
assert np.allclose(A @ x, b)
assert np.allclose(x, np.array([1, 2, 3], dtype=float))`
}]} />

The checks are part of the example because **factor order** and row-swap bookkeeping are common implementation errors.

The pivot tolerance is relative to the matrix infinity norm. Uniformly rescaling a well-conditioned system therefore does not trigger failure just because every entry is small. The threshold is a numerical decision, not proof of exact singularity.

## Scope of the method

This implementation solves systems only for **nonsingular square matrices** and treats a zero numerical pivot as a failure. Use <InlineMath math="\mathrm{QR}" /> for rectangular least-squares problems and column-pivoted <InlineMath math="\mathrm{QR}" /> or <InlineMath math="\mathrm{SVD}" /> for rank-deficient problems. A <InlineMath math="\mathrm{PLU}" /> factorization may still exist for a singular square matrix, but this solver cannot use it to obtain a unique solution.
