# Given

Pak Rudi's rule dropped the **fastest run (<InlineMath math="18" /> s, pushed by a gust)** and **slowest run (<InlineMath math="31" /> s, snagged on a branch)**, yet **the first answer (<InlineMath math="0.44" /> m/s) remained wrong** because the pacing mistake (<InlineMath math="9" /> m vs. <InlineMath math="10" /> m) affected every run equally.

# Asked

Which numbered statements the account shows about Pak Rudi's rule of crossing out two runs.

# Solution

See both **what trimming outliers fixes** and **what it cannot fix**: dropping the extremes cleanly removed the two disturbed runs (I and II), yet **it could not fix a systematic distance error** shared by every run (III), leaving the first answer wrong (eliminating IV).

> Trimming extreme runs protects an average against random one-off disturbances, never against a systematic measurement error built into every trial.

## Checking each statement about Pak Rudi rule

| Statement | Shown by account? | Direct evidence in the text |
| --- | --- | --- |
| I | **Yes** | The crossed-out runs (<InlineMath math="31" /> s snagged on a branch and <InlineMath math="18" /> s pushed by a gust) were the exact two runs observed to be disturbed. |
| II | **Yes** | Pak Rudi's stated purpose: <Highlight>because a single snag or gust can spoil one run</Highlight>. |
| III | **Yes** | Because the <InlineMath math="9" />-metre vs. <InlineMath math="10" />-metre error affected all runs equally, dropping two runs could not stop the wrong answer. |
| IV | No | Contradicted from the opening sentence: the first answer (<InlineMath math="0.44" /> m/s) was wrong for a week. |

## Why the other options fail

- **Options including IV** claim the rule made the first answer right, contradicting the entire recount.
- **I and II only** or **II and III only** drops either the systematic-error limit (III) or the exact match with the disturbed runs (I).

# Answer

The account shows **I, II, and III only**.
