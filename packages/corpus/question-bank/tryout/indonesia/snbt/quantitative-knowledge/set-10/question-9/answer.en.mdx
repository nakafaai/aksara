Each new square is attached to the previous one and shares one side, so **each pattern adds exactly 3 matches**. The numbers of matches form the arithmetic sequence 4, 7, 10 and so on.

# Formula for the nth term

<BlockMath math="U_n=4+(n-1)\cdot3=3n+1" />

The formula <InlineMath math="4n" /> only fits the first pattern, because **a shared side is not counted twice**. For example, pattern 2 needs 7 matches, not 8. The first statement is false.

# Using the formula

<BlockMath math="\begin{aligned}
U_{10}&=3\cdot10+1=31\\
U_{20}-U_{10}&=61-31=30
\end{aligned}" />

The second statement is true. The difference is 30, that is **10 extra patterns times 3 matches**, not 31. The third statement is false.

For 100 matches, solve <InlineMath math="3n+1=100" />, which gives <InlineMath math="n=33" />. Since 33 is a whole number, pattern 33 uses exactly 100 matches. The fourth statement is true.

So the first statement is **false**, the second is **true**, the third is **false**, and the fourth is **true**.
